# 06 状态与效果模型

> 数值与状态的统一模型：把"扣血/回血/BUFF/标记/翻面/到回合结束为止"归到同一套**带来源的修改**语言下。伤害不是特例，状态不只是 bool。
> 关系：交易（`04`）负责"要不要发生这件事"，本卷负责"发生后世界怎么变"。GAS 的 GE/ASC 承担执行载体，GAS 不裁决时序（时序归 `02`/`03`）。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 属性（Attribute）建模与修改入口 | 修改的时机裁决（窗口/交易在前端） |
| 效果（一次性/持续/周期）的声明与执行 | 效果由哪张牌/哪个技能产生（内容侧） |
| 状态的挂载、层数、到期、互斥、来源追溯 | 状态被谁用于裁决（语义层各自查） |
| 状态事件的广播（获得/失去/到期） | 客户端表现（`11`） |

## 2. 三个基本概念

### 2.1 属性 Attribute —— 世界的数字

| 属性 | 说明（示例为样本） |
|---|---|
| 生命值（及上限） | 归零进入濒死（`P5`） |
| 体力/能量类资源 | 技能消耗的通用计数资源 |
| 手牌相关计数 | 可被效果修改的"配额"型属性 |
| 元素损伤值/条（样本） | 每种元素一条独立属性（Max/Current + 变更广播，形状等同生命值）；条满触发的爆条类行为由专设组件订阅属性广播驱动（§4），不在伤害结算内附带 |

规则：
- 属性修改**只经"效果提交"入口**（见下），不散落直接赋值。
- 属性当前值本身派生状态（如 `生命 ≤ 0 → 濒死`）由**阈值订阅**驱动，不轮询。

### 2.2 效果 Effect —— 对世界的一次修改声明

```
EffectSpec（数据/声明）
    作用于：目标（可能多个，来自 `05` 锁定集）
    类型：立即修改属性 / 添加状态 / 移除状态 / 修改交易字段（配合窗口）……
    数值：固定值 / 属性倍率 / SetByCaller（由调用者定）
    属性组：修改哪个(些)属性

立即修改属性示例：-2 生命（伤害）；+1 生命（回复）
```

- 伤害 = `生命值` 的负修改 + 伤害标签（供防伤/减伤响应**在修改生效前**拦截）。
- 伤害标签（类型：物理/法术/真实，及元素子类等）**只作输入**：伤害结算本身不隐含附加任何状态或次级属性（元素损伤值/条，见 §2.1）；次级行为由专设机制订阅属性变化广播驱动——**引擎不因伤害标签产生副作用**。
- 回复/流失/扣体力是同一种形状的不同标签，**禁止为每种造一套引擎**。

### 2.3 状态 Status —— 一段带来源的生命期

```
StatusInstance
    状态标签（身份：BUFF/Debuff/标记/翻面/止息……只用标签，无特判）
    来源（谁给的：角色/牌/效果）—— 追溯与"来源死亡时"规则的数据基础
    生命期：永久 / 至回合结束 / 至本局结束 / 固定时长（回合数）
    层数（可无）与叠加上限
    附加修改（随状态存在的属性修正 / 标签封锁 / 状态专属效果）
```

| 状态能力 | 语义 | 例子（样本） |
|---|---|---|
| 到期 | 生命期到点自动移除并广播 | "翻面到下回合开始" |
| 层数 | 同一状态重复施加叠加层数，达上限拒绝或刷新 | 蓄力层数 |
| 互斥/替换 | 同组状态（如翻面类）互相替换 | 新的覆盖旧的 |
| 标签封锁 | 持有期间屏蔽某类行为 | "不能出伤害牌"类 |

## 3. 状态生命周期

```
施加：来源提交 EffectSpec → 目标侧裁决（互斥/上限/刷新）→ 挂载 → 广播事实(获得)
存活：状态自持到期计时（按回合推进减时，回合结束统一 tick）
移除：到期 / 效果移除 / 来源失效 → 卸载 → 广播事实(失去)
```

- 状态的**到期/刷新规则是状态自己的**：每种状态声明自己"重复施加"时的处理（叠加/刷新/拒绝），引擎只按声明执行。
- 状态只随时间与规则移除——**不允许"状态把字段改来改去再假装自己不在"**。

## 4. 状态与效果的事件（登记进 `03` 对齐表）

| 事件 | 通道 | 用途 |
|---|---|---|
| 状态获得 / 失去 | 事实通知 | UI、语音、被动订阅 |
| 属性变化 | 事实通知（含数值 delta） | 伤害数字、生命条、濒死检查触发器 |
| 生命 ≤ 0 阈值 | 派生事件 → `P5` 濒死流程 | 濒死不轮询，由阈值驱动 |

状态是**可以被查询**的（供 `05` 校验器、`10` 响应前提、`09` 激活条件），但"获得/失去状态"本身是已发生的事实——开窗口会卡死结算，故默认只有通知通道；确需干预（如"防止获得某状态"）时挂 `Timing.*` 族并明确登记，不默认开放。

## 5. 来源追溯（贯穿原则）

- 每次修改都携带来源链：`效果 → 技能体/牌 → 角色`。交易/状态/账本（`07`）都可查"这笔账谁造成的"。
- 来源死亡/离场时：其持续效果进入"结束处理"（到期或转归属规则），由来源字段裁决，不做全局搜索。

## 6. 执行载体（UE 落地：AttributeSet + GE + ASC）

| GAS 件 | 职责 | 约束 |
|---|---|---|
| `UAttributeSet` | 属性定义与 Clamp/后置（如濒死触发） | 只放属性与随属性后置逻辑 |
| `UGameplayEffect`（可运行时构造） | 效果声明的落地形态 | 伤害用 `SetByCaller` 携带交易数值 |
| `ASC`（挂 PlayerState） | 应用 GE / 持有附加状态 | 状态如用额外 GE 承载，到期=移除 GE |
| GameplayTag | 状态/效果的标签化 | 原生标签或数据资产，见 `03` §3.2 |

> 现有代码尚无 AttributeSet（P4 引入）。若现游戏是"自定义状态表"形态而非 GAS 满配，可先以"状态 = 注册表条目 + 每角色状态实例"落地，再逐步对齐 GAS 接口——但**属性修改入口与来源追溯原则从第一天生效**。

## 7. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `04`：交易收敛到修改 | 伤害交易 `Execute` = 提交一次带伤害标签的修改；不亲自写属性 |
| 对 `03`：状态事件登记 | 状态获得/失去 = 事实；属性变化 = 事实；阈值派生濒死 |
| 对 `05`：状态可被校验 | 校验器读状态标签，不写状态 |
| 对 `07`：状态可被计数 | 账本计数与状态生命周期正交 |
| 对 `09`：技能条件/代价 | 激活前提可查询状态；效果经本卷施加 |

## 8. 扩展点

- 新 BUFF/标记 → 数据资产加条目（标签 + 生命期/叠加/修正声明），引擎无改动。
- 新资源类型 → 属性表加属性；若需新"结算方式"再回到 `04` 判断是否需要新交易。
- 新状态行为 → 状态声明增一个生命周期策略实现（如自定义到期规则），按接口注册。

## 10. 案例（仅作样本，不进框架）

- "杀 1 点"= 交易开 `Damage.Incoming`（可防可改）→ `Execute` 提交 `{ -1 生命, 标签=伤害 }` → 生命变化通知 → 触发阈值检查。整个链条无"伤害特判"。
- 濒死求回应 = `生命 ≤ 0` 阈值派生 `UDyingTransaction`（`04`），其 `Execute` 因"救回"决定保留/归零。
- "回合结束消失的增益" = 状态生命期=至当前回合者回合结束；tick 统一处理。案例用途：统一到期模型。
