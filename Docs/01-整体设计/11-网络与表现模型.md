# 11 网络与表现模型

> 边界与呈现：服务器权威的落地规则、复制形态、客户端世界如何被驱动、玩家输入如何上行、表现如何不反压规则。战斗系统不做客户端预测。
> 关联：各卷"复制可见"的落点集中在此；客户端相关约定全卷适用。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 权威边界与改状态门控 | 规则裁决本身（`02`~`09` 各自） |
| 复制策略与 OnRep 分工 | 界面/动效具体实现（内容侧） |
| 客户端输入上行协议与校验 | 什么输入合法（`10` 校验在先） |
| 表现队列与 GameplayCue | 服务器结算是否等动画（绝不等） |

## 2. 权威边界（铁律）

| 类别 | 服务器 | 客户端 |
|---|---|---|
| 规则裁决（回合/时机/交易/账本/技能激活） | 唯一执行者 | 不执行 |
| 状态修改（阶段、区域、属性、状态实例） | 唯一写入者 | 只读复制值 |
| 流程推进（`Advance`/出队/开窗） | 唯一驱动者 | 无任何流程任务 |
| 输入裁决（发动/选目标/响应） | 校验后生效 | 提交意图 |
| 表现（动画/数字/牌飞） | 只发信号 | 本地播放 |

落地铁律：
- 所有改状态入口带 `IsRunningOnServer()`/`HasAuthority` 门控（现状已按此修正，持续审计）。
- 子系统创建条件按 `GetNetMode()`（`!= NM_Standalone`），专用服务器同样可用；权威改动统一走门控。

## 3. 客户端世界由三类输入驱动

```
① 复制属性   阶段/顺位/各区域(独立 OnRep)/属性值 —— 世界长什么样
② 事实通知   委托/Notify（阶段进入、牌已移动、伤害已结算）—— 世界刚发生什么
③ GameplayCue/表现信号  —— 瞬时演出（伤害数字、翻牌、牌飞行）
```

- 客户端**不订阅任何查询时机**，不接收窗口事件本体；只收"你有响应权 + 候选集"的表现形态。
- 阶段表现走复制 + RepNotify：客户端看到的是服务器状态的照片流，不自己推演。

## 4. 表现队列（规则与表现的唯一缓冲）

```
服务器结算快于表现 → 表现请求入队，本地顺序播放，追不上就攒
服务器结算慢于表现 → 队列空，等数据到达再播下一段
```

- 队列只在客户端；满/慢不影响服务器继续结算（无反压）。
- 表现请求带**可断言的排序依据**（阶段/交易序号或事件序号），回放与断线重连可据此对齐。

## 5. 玩家输入上行（交互层通道）

```
服务器开窗/开候选 → 客户端弹交互 → ServerRPC 提交
服务器按 10 §5 校验 → 通过才落地
```

- 客户端到服务器单向上行，无服务器主动推输入需求。
- 反外挂：服务器侧一切以**服务器持有状态**为准（候选集重算），不信任客户端自报的合法/非法。

### 5.1 下行通道：候选下发走 ClientRPC，不走属性复制（⑦ 口径，2026-09-16 定）

窗口候选是**点对点事件**，不是复制状态。四条理由：

1. **无复制载体**：窗口住在 `UBattleGameFlowSubsystem`（`UWorldSubsystem`）的 `TOptional<FResponseWindow>` 里
   （`12` 附录 C）——子系统不是 Actor/Component，没有 `GetLifetimeReplicatedProps` 可言；交易是裸 `UObject`
   （`NewObject` 创建、出队即用，`04` §2），同样不参与复制。为"让客户端看见窗口"去造一个复制载体，
   = 把 server 私产搬进网络层，方向反了。
2. **点对点，不是广播**：`InOrder` 逐个询问，同一时刻只有**一个**玩家有权响应（`10` §4）。属性复制是
   全客户端广播 + 最后值收敛，会把"该谁响应"泄露给所有人，还得在客户端分流。
3. **事件语义，不是状态收敛**：候选 = "请你在 T 秒内决定"的**请求**，丢了就永久丢了（窗口在原地等，
   引擎侧没有定时器兜底，`10` §4）；而复制是状态语义——重连/后加入的客户端会收到**过期的候选**并弹 UI。
   → 通道必须是 RPC，且**双向 Reliable**。
4. **序列化约束**：`FResponseWindow` 含 `TStrongObjectPtr<UBattleTransaction>`，既进不了复制属性、也作不了
   RPC 参数（RPC 参数走序列化，与复制同族约束）。→ 必须**拍平 DTO**（§5.2）。

> 结论：**"客户端看见窗口"这件事上，引擎只做两件网络动作**——`ClientRPC` 下发候选 DTO、`ServerRPC` 收回传。
> 除此之外窗口、交易、C 面委托一律留在服务器，不进复制。

### 5.2 响应交互协议（⑦ 落地形状，服务端落点已在场）

```cpp
// 下行：候选 DTO —— 窗口形状里唯一 USTRUCT 化的一份（服务器 → 客户端，ClientRPC 参数）
// 不带交易引用：客户端不认识 UBattleTransaction（它不复制），只认句柄与展示数据
USTRUCT()
struct FClientResponseWindow
{
    GENERATED_BODY()

    int32 WindowSerial = 0;              // 不透明句柄：回传时服务端校验"这就是当前窗口"（防陈旧/重放）
    FGameplayTag Timing;                 // 展示用（"现在是 XX 时机"）
    float Timeout = 0.f;                 // 时间预算（UI 倒计时；引擎侧无定时器，10 §4）
    FGameplayTagContainer Candidates;    // 该玩家的候选技能 tag（从 Responders 里 Owner == 该玩家 的 Key 溢出）
    bool bHasTransaction = false;        // 纯阶段窗 = false（客户端不猜交易语义）
};

// 上行：响应意图（不是 ModRequest）——服务端自己决定该意图产生什么修改
USTRUCT()
struct FWindowResponseRequest
{
    GENERATED_BODY()

    int32 WindowSerial = 0;              // 必须等于当前窗序号，否则视为陈旧，忽略
    FGameplayTag Skill;                  // 我选择用哪个技能响应（必须在 Candidates 内）
    // 目标/代价参数随访 P5/P6 扩展
};

// PlayerController（**唯一的 UI 转发口**；与既有选择输入协议——选角 `TrySelectOperator`——同侧）：三壳纯转发、零信任
// 命名随既有 RPC 家族（`Server_MoveCard` 等）取 `Client_` / `Server_` 前缀
UFUNCTION(Client, Reliable) void Client_OpenResponseWindow(const FClientResponseWindow& Window);
UFUNCTION(Server, Reliable) void Server_SubmitWindowResponse(const FWindowResponseRequest& Req);
UFUNCTION(Server, Reliable) void Server_DeclineWindowResponse(int32 WindowSerial);
```

> **代码现状（2026-09-17 复核）**：两端 DTO 落 `EventTypes.h:55-93`，三壳落 `BattlePlayerController.h:138/141/145`，
> 三处已知缺陷（下行壳漏形参 / `Decline` 误标 `Client` / 三壳无 `_Implementation`）**已于 2026-09-17 第六轮全部修毕**：
> 三 `_Implementation` 齐备（`.cpp:99/114/137`），下行带 `const FClientResponseWindow&`，`Decline` 归 `Server`。
> ⚠ 上条行号因选角区段插入已整体后移（`.h` / `.cpp` 均在其后），**定位请以函数名为准**。
>
> **选角 RPC 归位（2026-09-18）**：`Server_OnOperatorSelected` / `Client_NotifySelectOperator` 原挂 `ABattlePlayerState`，现迁至
> `ABattlePlayerController`——上行 `TrySelectOperator`（内转 private `Server_SelectOperator`，判空与告警照 `Server_SubmitWindowResponse` 的零信任写法），
> 下行 public `Client_NotifySelectOperator`（服务器侧由模式组件调用）配客户端侧定向委托 `OnOperatorSelectRequested`（声明见 `12` §附录 A）。
> PlayerState 只留业务入口 `ApplyOperatorSelection` 与复制字段 `Operator`；`IPlayerOperatorInterface` 随之瘦身至仅 `GetOperator`（`13` §2.2）。
> 判据即本节口径——零信任 + UI 只经 PC：**RPC 收发口不挂个体状态机**。本条同时是 §5.2 注释里"（或 `PlayerOperatorInterface`）"括号的定案。

- **`Responder` 由服务端从 RPC 发起者解析**（`PlayerController->GetPlayerState()`），**绝不采信客户端自报身份**；
  随后照旧走既有服务端落点 `SubmitWindowResponse(Responder, Req)` / `DeclineWindowResponse(Responder)`
  （二次校验 = 窗口在场 + 锁内 + **句柄等于本窗** + 提交者与所选技能落在【待回位】上——`InOrder` 认游标处那一条
  且 Key 须与之相符，同开类按 Key 在本人待回条目里挑；服务端把意图翻译成 `FTransactionModRequest`）。
- **`WindowSerial`** 由子系统开窗时自增（**待落字段**，⑦ 施工内容）：陈旧/伪造回传直接忽略。
- **`FTransactionModRequest` 保持普通结构体**（server 内部收敛载体，永不过网）；**唯一上反射的是两端 DTO**——
  与 `FResponseWindow`/`FResponseEntry` 维持普通结构体的口径同源（`12` 附录 C）。
- 双向 **Reliable**：候选丢一次 = 玩家永远不弹 UI = 窗口悬挂（无定时器兜底）；回传丢一次 = 该玩家作废一次
  响应权（不致命，但与下行保持同一口径）。
- 掉线悬停无服务端兜底是**刻意保留的已知边界**（P3 口径，P7 接 UI 时复核），本阶段不加引擎定时器。

## 6. 网络模式与部署

| 模式 | 支持 |
|---|---|
| 独立服务器 / Listen | 是（子系统 `GetNetMode()` 创建） |
| Standalone 单机调试 | 流程门控放行（`IsRunningOnServer` 真），便于无网调试 |
| 分房间/大厅 | 对局用 GameState 承载，与既有 GameMode/PlayerController 分层一致 |

## 7. 回放与指令队列（可选收尾，交易即数据源）

- 交易队列 + 时机/通知事件天然是**指令流**：记录"入队交易 + 窗口响应 + 收敛结果"即可回放，无需记录每帧状态。
- 回放与录像作为 P7 扩展，不做进引擎核心。

## 8. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `02`：阶段事实 | OnRep/委托消费，无流程任务 |
| 对 `03`/`10`：窗口事件 | 客户端只收"表现形态"（候选/你有权响应），不参与裁决；下行通道 = ClientRPC 点对点（§5.1），非复制 |
| 对 `04`/`08`：交易/移动结果 | 经复制可见；服务器不等动画 |
| 对 `06`：状态表现 | 状态实例随属性/标签复制，Cue 出特效 |

## 9. 扩展点

- 新表现 → 加 Cue/表现信号 + 客户端队列项，服务器规则零改动。
- 新客户端交互 → 提交 RPC 加数据形状（校验不变）。
- 录播/观战 → 挂事件订阅器导出指令流，不侵入结算。
