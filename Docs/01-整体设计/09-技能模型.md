# 09 技能模型

> 技能 = **声明（数据）** + **技能体（GAS Ability）**。引擎只认形状：任何技能（角色技、装备技、牌衍生效用）都是"声明 + 技能体"这个形状的实例。
> 落地：`USkillManagerSubsystem`（注册表 + 时机索引）+ 技能体（`Battle/Abilities/`，ServerOnly）+ 玩家侧 `USkillComponentBase`（实例宿主，挂 PlayerState）。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 技能声明、激活方式、时机索引 | 目标与距离（`05`）、频率（`07`）的裁决——以查询/声明的形式接入 |
| 技能体宿主与 Grant | 响应窗口询问策略（`10`） |
| 触发判定（该不该问/该不该自动） | 状态/效果的落地（`06`） |
| 技能的修改/觉醒（演化） | 具体某个技能的内容（内容侧） |

## 2. 声明（数据侧，无行为）

```cpp
// FSkillInfo —— 声明字段
FGameplayTag SkillTag;                       // 技能身份（语音/文案/账本键共用）
FGameplayTagContainer ListenTimings;         // 监听的时机点（03 索引源）
ESkillActivateType ActivateType;             // 激活方式标志（见 §4，不是行为分支）
bool bAskFirst;                              // 到达时机是否"询问是否发动"（false=全自动）
TSubclassOf<UGameplayAbility> AbilityBody;   // 技能体（行为实现）
int32 ResponsePriority = 0;                  // 同一时机多技能时的响应次序（10 用）
// 频率能力（07）：
FGameplayTag FrequencyKey; int32 MaxUsesPerRound, MaxUsesPerGame; bool bPerOwner;
// 目标能力（05）：FTargetSpec 或指向目标规则的引用
TSoftObjectPtr<FTargetRuleData> TargetRule;
// 演化（§7）：原始声明引用（觉醒/修改产生副本）
TObjectPtr<FSkillInfo> BaseSkill; int32 EvolutionGen = 0;
```

## 3. 触发判定（流程侧的形状，认识所有技能）

```
时机开窗 / 广播（03）
   → SkillManager 时机索引命中监听技能列表
   → 逐个技能问三件事：
       ① 该技能此刻合法吗？（来源在场/可用/状态允许/账本够 → 07 预检 / 06 状态查询）
       ② 该技能要不要现在触发？（bAskFirst：询问（10）；false：全自动直接激活）
       ③ 若触发，目标是谁？（ResolveTargets（05））
   → 玩家确认/自动 → TryConsume（07）→ TryActivateAbility（技能体）
```

- **流程不认识技能，只认上述形状**；具体逻辑全在技能体内（AbilityTask 串联 `04` 交易、`06` 修改、`03` 二次时机）。
- 锁定技与自动被动在引擎眼里同一种：`bAskFirst=false` + 时机触发，锁定与否只是"是否可被弃置/无效"的附加标签，不由引擎特判。

## 4. 激活方式标志（避免"类型=行为"陷阱）

现有 `ESkillActivateType` 的语义应**降维成标志组合**，别在引擎里 switch 角色类型：

| 旧类型 | 还原为标志 |
|---|---|
| 被动技 / 锁定技 | 时机触发 + `bAskFirst=false`（自动） |
| 主动技 | 玩家主动输入（ServerRPC）触发 + 流程合法性校验 |
| 限定技 | 主动技 + `MaxUsesPerGame=1`（账本配置，不是新类型） |
| 策略技 / 指挥技 | 主动技 + 特殊前提（目标/时机/状态前置在声明与技能体里） |

落地形态：激活方式 = `bAutoOnTiming / bAskFirst / bPlayerInitiated` 等布尔 + 账本/目标字段组合。**新"类型"= 新的标志组合**，而不是新代码分支。

## 5. 技能体（行为实现）

- 一律 `ServerOnly` 网络策略；`InstancedPerActor`（允许并发实例）。
- 与窗口衔接：等待类技能体内部用 AbilityTask 串联（见 `10`）；触发类靠 `HandleGameplayEvent` 或流程显式 `TryActivateAbility`。
- 技能体是**唯二**可以"认识具体机制"的地方之一（另一个是内容侧数据）——它负责本技能的独特规则，绝不允许把独特规则上移进引擎。

## 6. 宿主与生命周期

- 战斗开始：`USkillComponentBase`（PlayerState）把当局技能实例的 `AbilityBody` Grant 给该玩家 ASC。
- 技能可用状态：由声明 + 现场（账本/状态/时机）实时裁决，不做"技能列表里藏 bool"。
- 技能被无效/弃置（如装备技随装备离场）：Grant/RemoveAbility 随持有物生命周期，由持有物事件驱动。

## 7. 技能演化（觉醒/修改技的通用处理）

> "觉醒后技能替换/强化""修改技变体"若让技能系统识别每个变体 = 灾难。统一模型：

- **演化 = 派生声明副本**：修改发生时以原声明为底生成 `EvolutionGen+1` 的副本（改监听时机/上限/目标/绑定新技能体），旧实例撤销、新实例 Grant。
- 账本键带 `EvolutionGen`（`07`），演化后重新计数（沿用规则由数据声明），天然隔离。
- 状态与来源追溯（`06`）记录演化触发者，供"结算时按觉醒后技能口径"查询。
- 引擎侧无任何"觉醒"概念——就是一次声明替换事件（事实通知：技能变化）。

## 8. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `03`：索引与唤醒 | 时机索引由注册表维护；窗口策略决定唤醒次序（`10`） |
| 对 `07`：频率 | 预检/消耗/演化换代经账本统一入口 |
| 对 `05`：目标 | 声明含 TargetRule，激活时裁决 |
| 对 `10`：询问 | bAskFirst 技能进询问通道；全自动直接激活 |
| 对 `06`：效果 | 技能体输出效果描述符经状态模型施加 |

## 9. 扩展点

- 新角色技能 → 加声明行 + 写一个技能体（形状第 7 类），引擎零改动。
- 新激活形态 → 加标志位组合并登记激活判定（若产生新引擎行为，先回 `01` 评审）。
- 新演化方式 → 只换"派生声明"的生成规则，宿主与账本不变。

## 10. 落地与状态

| 项 | 现状 |
|---|---|
| `USkillManagerSubsystem` | 注册表已有；时机 → 技能索引待加（P3 起逐步） |
| `USkillComponentBase` | 已挂 PlayerState（`Battle/Component/Skill/`），实例宿主语义按本卷对齐 |
| 技能体目录 | `Battle/Abilities/`（P3 建首批：窗口持有技能 + 测试技能） |
| 技能声明数据 | 设定表侧已有素材；字段按 §2 展开（P3/P6） |
| 演化 | 未落地（P6 与账本换代一起） |

## 11. 案例（仅作样本，不进框架）

- "收到伤害前可发动：红桃则无视"：声明（监听 `Damage.Incoming`、bAskFirst=true、目标=自己）→ 技能体（摸一张→判定→若红桃改交易字段）。案例用途：交易 + 时机 + 技能三卷走通。
- "觉醒"：到达条件 → 流程生成 `EvolutionGen+1` 声明副本并替换。案例用途：演化模型。
