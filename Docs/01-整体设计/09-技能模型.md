# 09 技能模型

> 技能 = **声明（数据）** + **技能体（GAS Ability）**。引擎只认形状：任何技能（角色技、装备技、牌衍生效用）都是"声明 + 技能体"这个形状的实例。
> 落地：`USkillManagerSubsystem`（注册表 + 时机索引）+ 技能体（`Battle/Abilities/`，ServerOnly）+ 玩家侧 `USkillComponentBase`（实例宿主，挂 PlayerState）。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 技能声明、激活方式、时机索引 | 目标与距离（`05`）、频率（`07`）的裁决——以查询/声明的形式接入 |
| 技能体宿主与 Grant | 响应窗口询问策略（`10`） |
| 触发判定（该不该问/该不该自动） | 状态/效果的落地（`06`） |
| 技能的修改/觉醒（演化） | 具体某个技能的内容（内容侧） |

## 2. 声明（数据侧，无行为）

```cpp
// FSkillInfo —— 技能声明（数据侧，无行为；目标形态完整定义）
USTRUCT()
struct FSkillInfo
{
    FGameplayTag SkillTag;                        // 技能身份（语音/文案/账本键共用）
    FGameplayTagContainer ListenTimings;          // 监听的时机点（03 索引源）

    // 激活方式 = 标志组合（§4；旧 ESkillActivateType 降维为组合，不再是"行为类型"字段）
    bool bAutoOnTiming = false;                   // 时机触发（锁定/全自动被动）
    bool bAskFirst = false;                       // 到达时机先"询问是否发动"（false + bAutoOnTiming = 全自动）
    bool bPlayerInitiated = false;                // 玩家主动输入（ServerRPC）触发（§4 表"主动技"）

    TSubclassOf<UGameplayAbility> AbilityBody;    // 技能体（行为实现）
    // 无技能级 ResponsePriority：响应次序是局面属性而非技能属性——
    // InOrder 名单序 = 座次（开窗实时读），All/FirstOnly 同时发生无序（10 §2）

    // 频率能力（07 §4）：账本键族 + 上限；空键/0 = 不限
    FGameplayTag FrequencyKey;
    int32 MaxUsesPerRound = 0;
    int32 MaxUsesPerGame = 0;
    bool bPerOwner = true;

    // 目标能力（05 §3.2）：目标规则数据资产（UTargetRuleData 完整定义见 05 附录，内含 FTargetSpec + 注册键）；空 = 无目标限制
    TSoftObjectPtr<UTargetRuleData> TargetRule;

    // 演化（§7）：原始声明引用（觉醒/修改产生副本）
    TObjectPtr<FSkillInfo> BaseSkill;
    int32 EvolutionGen = 0;
};
```

## 3. 触发判定（流程侧的形状，认识所有技能）

```
时机开窗 / 广播（03）
   → SkillManager 时机索引命中监听技能列表
   → 逐个技能问三件事：
       ① 该技能此刻合法吗？（来源在场/可用/状态允许/账本够 → 07 预检 / 06 状态查询）
       ② 该技能要不要现在触发？（bAskFirst：询问（10）；false：全自动直接激活）
       ③ 若触发，目标是谁？（ResolveTargets（05））
   → 玩家确认/自动 → TryConsume（07）→ TryActivateAbility（技能体）
```

- **流程不认识技能，只认上述形状**；具体逻辑全在技能体内（AbilityTask 串联 `04` 交易、`06` 修改、`03` 二次时机）。
- 锁定技与自动被动在引擎眼里同一种：`bAskFirst=false` + 时机触发，锁定与否只是"是否可被弃置/无效"的附加标签，不由引擎特判。

## 4. 激活方式标志（避免"类型=行为"陷阱）

现有 `ESkillActivateType` 的语义应**降维成标志组合**，别在引擎里 switch 角色类型：

| 旧类型 | 还原为标志 |
|---|---|
| 被动技 / 锁定技 | 时机触发 + `bAskFirst=false`（自动） |
| 主动技 | 玩家主动输入（ServerRPC）触发 + 流程合法性校验 |
| 限定技 | 主动技 + `MaxUsesPerGame=1`（账本配置，不是新类型） |
| 策略技 / 指挥技 | 主动技 + 特殊前提（目标/时机/状态前置在声明与技能体里） |

落地形态：激活方式 = `bAutoOnTiming / bAskFirst / bPlayerInitiated` 等布尔 + 账本/目标字段组合。**新"类型"= 新的标志组合**，而不是新代码分支。

## 5. 技能体（行为实现）

- 一律 `ServerOnly` 网络策略；`InstancedPerActor`（允许并发实例）。
- 与窗口衔接：等待类技能体内部用 AbilityTask 串联（见 `10`）；触发类靠 `HandleGameplayEvent` 或流程显式 `TryActivateAbility`。
- 技能体是**唯二**可以"认识具体机制"的地方之一（另一个是内容侧数据）——它负责本技能的独特规则，绝不允许把独特规则上移进引擎。

## 6. 宿主与生命周期

- 战斗开始：`USkillComponentBase`（PlayerState）把当局技能实例的 `AbilityBody` Grant 给该玩家 ASC。
- 技能可用状态：由声明 + 现场（账本/状态/时机）实时裁决，不做"技能列表里藏 bool"。
- 技能被无效/弃置（如装备技随装备离场）：Grant/RemoveAbility 随持有物生命周期，由持有物事件驱动。
- **时机订阅（听哪些时机）归技能组件子类**：基类 `USkillComponentBase` 只做宿主与便利（`CreateSkill` 工厂 / `GetSkillTag()` / `OnCanActivate()` 钩子），**不规定**听哪些时机、何时订阅、要不要统一登记口，也不代劳登记——子类自行向 `USkillManagerSubsystem` 的时机索引 `RegisterSkillTiming` / `UnregisterSkillTiming` 订与退（`03` §5、`P3` §3.3.1）。订阅集合因此是子类实现细节，不上升为声明数据字段。

## 7. 技能演化（觉醒/修改技的通用处理）

> "觉醒后技能替换/强化""修改技变体"若让技能系统识别每个变体 = 灾难。统一模型：

- **演化 = 派生声明副本**：修改发生时以原声明为底生成 `EvolutionGen+1` 的副本（改监听时机/上限/目标/绑定新技能体），旧实例撤销、新实例 Grant。
- 账本键带 `EvolutionGen`（`07`），演化后重新计数（沿用规则由数据声明），天然隔离。
- 状态与来源追溯（`06`）记录演化触发者，供"结算时按觉醒后技能口径"查询。
- 引擎侧无任何"觉醒"概念——就是一次声明替换事件（事实通知：技能变化）。

## 8. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `03`：索引与唤醒 | 时机索引由注册表维护；窗口策略决定唤醒次序（`10`） |
| 对 `07`：频率 | 预检/消耗/演化换代经账本统一入口 |
| 对 `05`：目标 | 声明含 TargetRule，激活时裁决 |
| 对 `10`：询问 | bAskFirst 技能进询问通道；全自动直接激活 |
| 对 `06`：效果 | 技能体输出效果描述符经状态模型施加 |

## 9. 扩展点

- 新角色技能 → 加声明行 + 写一个技能体（形状第 7 类），引擎零改动。
- 新激活形态 → 加标志位组合并登记激活判定（若产生新引擎行为，先回 `01` 评审）。
- 新演化方式 → 只换"派生声明"的生成规则，宿主与账本不变。

## 10. 落地与状态

| 项 | 现状 |
|---|---|
| `USkillManagerSubsystem` | 注册表已有；⚠ 时机索引本体已落（P3：`SkillTimings` + `RegisterSkillTiming`/`UnregisterSkillTiming`/`GetSkillListeners`，服务器门控 + 验活 + 查重）；开窗侧接线与技能子类的订阅/退订（基类不做限制）待补 |
| `USkillComponentBase` | 已挂 PlayerState（`Battle/Component/Skill/`）；✅ `CreateSkill` 工厂（查重 → 取声明 → `bDeferred` 注册 → 挂 `ComponentTags`）/ `GetSkillTag()` / `OnCanActivate()` 时机钩子已落；**时机订阅/退订由子类自行实现（基类不规定听哪些时机、何时订阅，也不代劳）**，待内容侧技能子类落地 |
| 技能体目录 | `Battle/Abilities/`（P3 建首批：窗口持有技能 + 测试技能） |
| 技能声明数据 | 设定表侧已有素材；字段按 §2 展开（P3/P6） |
| 演化 | 未落地（P6 与账本换代一起） |

## 11. 案例（仅作样本，不进框架）

- "收到伤害前可发动：红桃则无视"：声明（监听 `Damage.Incoming`、bAskFirst=true、目标=自己）→ 技能体（摸一张→判定→若红桃追加 `Ignore` 修改请求，落地 `bIgnored`，见 `04` §4/§8）。案例用途：交易 + 时机 + 技能三卷走通。
- "觉醒"：到达条件 → 流程生成 `EvolutionGen+1` 声明副本并替换。案例用途：演化模型。
- "令一名玩家下一张使用/打出的牌无效"（样板，A 角色技）：
  施加：技能把一层普通状态（层数 1）挂到被限制玩家（`06`，引擎不认识"拦截"）；
  触发：技能体监听 `PlayCard.Use` 与 `PlayCard.Respond` 两族时机（`03`），命中且出牌方带该状态 → 把该笔出牌交易标 `bNullified`（`04` 吞效果：移动照走、效果跳过、账本照记）→ 移除状态；
  范围（只拦"使用"/只拦"打出"/两者、持续几次）由效果数据声明。案例用途：验证"拦截类机制 = 状态 + 时机监听 + 交易结果位"的形状拼装，引擎零新增分支。
- "庇护：受到的伤害至多 1"（样板，与上例并列的防护类拼装）：
  施加：给目标挂"庇护"状态（`06`，生命期由状态管，自身无数值语义、不带行为）；
  触发：技能体监听 `Damage.Incoming`（`03`），命中且承受者带庇护 → 追加 `Clamp` 修改请求（`04` §4 折叠），不覆盖 `Amount`、不参与优先级竞争；多庇护并存由 clamp 组取更小自动收敛，状态到期/移除即停止追加。
  案例用途：验证"防护/封顶 = 状态（存在期）+ 窗口修改请求（行为）"——clamp 是交易级折叠，不是属性修正、也不是状态能力；与上例"拦截 = 状态 + 时机监听 + 结果位"是同族不同 Op 的两种拼装，引擎零新增分支。
