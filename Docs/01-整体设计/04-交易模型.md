# 04 交易模型

> 结算载体：一切"会发生事"都做成有生命周期的交易对象。"延迟结算"即交易悬停在查询阶段——**交易就是停泊点，不依赖任何函数栈存活**。
> 落地：`Battle/Transaction/`（`UBattleTransaction` 基类与子类同目录）+ 流程子系统交易队列驱动。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 交易生命周期（四态）与统一终局 | 时机如何开窗收响应（`03`/`10`） |
| 交易队列、忙锁、嵌套规则 | 阶段怎么走（`02`） |
| 落子动作的执行入口（子类 `Execute`） | 具体规则数值判定（数据/语义层） |
| 交易对状态/容器的最终写入（经接口） | 复制与客户端表现（`11`） |

## 2. 生命周期（四态）

```cpp
enum class EState : uint8 { Created, Querying, Executed, Finished };
```

```
创建方(Begin) ──> Created ──Enqueue──> [驱动]
                驱动──(P3+)QueryTimings──> Querying（窗口悬停；可修改/防止）
                最终收敛 ──> Executed（Execute 落子）/ Cancel（不落子）
                两者统一 ──> Finished ──回调管理器──> 踢下一条
```

| 方法 | 谁调用 | 职责 |
|---|---|---|
| `Begin()` | 创建方（阶段体/技能/调试） | 校验必填 → `Created` → 入队 `EnqueueTransaction(this)` |
| `QueryTimings()` | 管理器（P3 起；现为占位空转） | 逐个开 `03` 查询时机窗口 |
| `OnWindowClosed()` | 窗口关闭（P3） | 汇总结果 → 走 `Execute` 或 `Cancel` |
| `Execute()` | 管理器 / 窗口收敛 | 纯虚。真正的落子，**结束时必须自收尾**：`Finish()` 或 `Cancel()` |
| `Finish()` | `Execute` 成功路径 | `Finished` + 事实通知 + 回调管理器踢下一条 |
| `Cancel()` | 被防止/无效 | `Finished`（不落子）+ 被防止通知 + 踢下一条 |

要点：
- **Execute 自收尾**，两条生命路径都收敛到"回调管理器 → 继续"，对外接口不变；P3 引入异步窗口只是把 `Drive` 里 `Execute` 换成 `QueryTimings`，收尾链一行不改。
- 交易是 `UObject`，流程侧 `NewObject` 创建，出队即用；不挂 Actor、不参与复制（结果经容器/属性复制可见，见 `08`/`11`）。
- 交易字段（数值、目标、是否被防止）是窗口修改的对象——`03` 的负载即交易引用。

## 3. 队列与忙锁（不递归，排队执行）

```cpp
TArray<TObjectPtr<UBattleTransaction>> PendingTransactions;  // FIFO
TObjectPtr<UBattleTransaction> ActiveTransaction;            // 忙锁：非空 = 执行中 /（P3）窗口悬停

EnqueueTransaction(Tx)     // 入队；空闲则 DriveTransaction
DriveTransaction()         // 忙则直接返回；出队首置 Active 并驱动
OnTransactionFinished(Tx)  // 校验是当前 Active → 清空 → 再 Drive 踢下一条
```

- **忙锁是窗口悬停期的唯一锁**：`Execute` 期间若又 `Enqueue` 新交易（响应/派生结算），只入队不驱动；当前交易收尾后自然轮到——天然"串行结算、不递归"。
- **嵌套（唯一插队口）**：规则指定的打断（如濒死结算打断当前流程）用显式**嵌套栈**管理，不做隐式递归。P3 先留字段与入口，不实现。
- 所有方法 `IsRunningOnServer()` 门控；客户端不跑交易。

## 4. 交易子类（形状，不是家族特判）

子类只需实现三件事：声明**自己携带什么意图**、在**哪些时机被查询/通知**（`03` 对齐表登记）、`Execute` 里**经接口落子**。引擎不认识任何具体子类：

| 子类 | 意图载体 | 落子动作 | 查询时机（登记于 `03`） |
|---|---|---|---|
| `UCardMoveTransaction` | `FMoveMessage` 解析意图（From/To/Num/Order） | 容器 `MoveOut`/`MoveIn`（`08`） | `Card.Move` |
| `UDamageTransaction` | 来源/目标/伤害类型/数值/是否忽略 | 对目标侧语义层提交"数值修改"（`06`） | `Damage.Incoming / Dealt` |
| `UDyingTransaction`（后） | 濒死目标/已求回应数 | 救回或淘汰终局 | `Dying` |
| 使用类交易（后） | 被使用的牌 + 目标集 | 消耗牌 + 触发效果 | `PlayCard.Use`（响应链） |

伤害悬置的本质：窗口开着、`Execute` 未调用，交易对象本身就是停泊点——不需要暂停任何任务。

## 5. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `02`：阶段体/技能创建交易 | `Begin()` 入队即可，无需关心驱动细节 |
| 对 `03`：窗口负载 = 交易 | 修改交易字段 → 收敛 Execute/Cancel |
| 对 `06`：`Execute` 提交修改 | 只经"效果描述符/接口"，交易不直接写属性 |
| 对 `08`：`Execute` 移动牌 | 只经 `ICardContainerInterface` |

## 6. 扩展点

新增一种"结算行为"（如扣体力、弃牌、回收）：
1. 继承 `UBattleTransaction`，定义意图载体字段；
2. 实现 `Execute`（自收尾）；在 `03` 对齐表补一行时机登记；
3. 结束。**不碰**队列、不碰驱动、不碰其他交易。

新交易入队时机由调用方决定（阶段体 / 技能响应 / 另一个交易的 `Execute`），队列引擎无感。

## 8. 案例（仅作样本，不进框架）

- 摸两张：`NewObject<UCardMoveTransaction>` → `Move = "NUM=2 FROM=-AP TO=-AH"` → `Begin()`。
- "红桃则无视伤害"：技能在 `Damage.Incoming` 窗口内改 `bIgnored`（或调 `Cancel`）——交易的查询时机给了"阻止/防止"的口子，而无视伤害的判定逻辑全在技能体里（数据侧）。
- 濒死打断当前结算：濒死交易经嵌套栈插队，救回/淘汰终局后回到被挂起的交易。案例用途：验证嵌套栈语义（P5 验证）。
