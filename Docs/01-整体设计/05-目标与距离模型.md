# 05 目标与距离模型

> 语义层第一刀：把"这牌/这技能能用向谁"从结算逻辑里拆出来，成为可注入的裁决。任何涉及指定/选目标/作用范围（单体/多选/全场/距离受限）的机制都走本模型。
> 本卷为**接口与规则形状**，不绑定"杀要有距离"这类具体规则（那是案例与数据）。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 目标集的构成（候选、上限、下限、是否允许无目标） | 交易如何执行效果（`04`） |
| 合法性裁决（校验器链） | 响应窗口的询问顺序（`10`） |
| 距离/范围的计算接口与注入 | 座位与角色的产生（对局生命周期） |
| 选择来源（玩家选 / 规则自动） | 客户端选牌交互表现（`11`） |

## 2. 目标作为"目标描述 + 目标集"两级

```
目标描述 TargetSpec（数据/声明）
    候选范围（对象池：所有存活 / 距 X 内 / 持有某状态 / 牌在装备区……）
    合法性校验器列表（链式，全部通过才合法）
    数量约束（min / max / 恰好 N / 不选可 / 自动唯一）
    （可选）距离约束 / 范围覆盖（对区域牌的目标化）

目标集 TargetSet（结算期实例）
    由 描述 × 现场状态 裁决得出
    选择完成即锁定（响应期外不可再改，防时序竞态）
```

- "目标"的泛化：既可是玩家/角色对象，也可是**区域里的牌**（选牌）、**整类对象**（全场各弃一）——统一为 `Targetable` 接口（含对象身份、存活/在场状态、当前区域）。
- 目标集锁定在**使用/技能生效前**：后续响应链若使目标失效（死亡/离场/状态消失），用"目标失效 → 终止对该目标的效果/交易取消分支"处理（`10` 响应链的失效传播）。

## 3. 裁决协议

```cpp
// 语义层：纯函数 + 可注入校验器，无状态、不碰窗口与复制
struct FTargetSpec
{
    EObjectPool Pool;                     // 候选池描述
    TArray<TObjectPtr<ITargetValidator>> Validators;  // 校验器链
    int32 MinTargets = 1, MaxTargets = 1;
    bool bAllowZero = false;              // 可否选 0
    bool bForceSelection = false;         // 是否强制（锁技自动选）
};

// 核心动作（引擎实现，校验器可插拔）
TargetSet ResolveTargets(const FTargetSpec& Spec, const FGameplayTagContext& Ctx);
bool IsValidTarget(const Targetable& T, const FTargetSpec& Spec, const FGameplayTagContext& Ctx);
```

### 3.1 校验器（单一职责，可组合）

| 校验器 | 判断 | 复用场景（示例） |
|---|---|---|
| 存活校验 | 对象是否存活/在场 | 所有作用于角色的效果 |
| 身份校验 | 是否自己/队友/敌方 | 增益给己方、伤害给敌方 |
| 区域校验 | 对象当前在某区域/牌在某区域 | 手牌/装备区/判定区为对象 |
| 占用校验 | 目标对象对应区域对某内容是否已满/已含同种 | 判定区"同种唯一"收单过滤（目标判定区已含同种即非法，`08` §8） |
| 距离校验 | 与来源距离是否 ≤ R | "攻击距离"类受限目标 |
| 状态校验 | 是否带某状态/标签 | 只对"标记"目标的结算 |
| 自定义 | 数据侧新写校验器实现 | 策划新增的专属限制 |

> 规则：**引擎只提供校验器接口与常见实现的注册表**；特定限制 = 数据声明组合已有校验器，或内容侧新注册一个校验器——两者都不碰裁决主流程。

### 3.2 使用门槛：无合法目标即无使用入口

对"某张牌/某技能能用向谁"的预检与使用是**同一裁决**：能发起 = 当前状态下目标描述可解出非空目标集（且不允许零目标）。解空时该牌/技能当前不可使用——UI 不提供"使用"入口（按钮），也不产生使用交易（`04`）。裁决纯只读：客户端可先行用于入口显隐，服务器在交易内复判（`11`）；结果只表达"有/无"，不分类原因。

- **目标描述按种类/技能声明并注册**：判定牌、普通锦囊、技能各自持有自己的 `TargetSpec`；裁决主流程不写具体牌分支——"某种牌能用向谁"是数据/注册项而非引擎逻辑。
- **校验器只读现场状态，禁止写状态**：输入仅来自属性、标签、距离、容器内容查询等；技能/状态对"能否使用、能否被指定为目标"的限制一律以**状态形式**存在（如"禁止本回合对自己用锦囊""无法被指定为目标"等标签，由状态校验器读取）——裁决不区分限制来自规则还是技能，也不提供代码注入钩子。
- **面向区域的约束走区域内容查询**：如判定区"同种唯一"由占用校验器读取目标对象的判定区视图（`08` §2/§4/§8）实现；区域只出只读视图，不解释意图。

## 4. 距离与座位（可注入 Provider）

距离不内置任何算法，座位由对局生命周期生成：

```cpp
// 座位布局 Provider（可换实现：环形桌 / 无距离模式 / 跨区）
struct ISeatLayout { int32 DistanceBetween(Targetable A, Targetable B); };

// 距离修正（装备/技能/状态），外部挂接
struct IRangeModifierProvider
{
    int32 GetAttackRange(APlayerState* Actor);      // 攻击范围 = 基础 + 修正
    int32 GetModifiedDistance(Targetable Src, Targetable Dst); // 距离修正查询
};
```

- 距离只有被目标描述**引用**时才参与裁决（`距离校验器` 传入 `Range`），流程与交易不直接查距离。
- 修正来源（武器、技能、状态）各自向 `IRangeModifierProvider` 注册修正项；**谁加范围归谁维护**，避免全局改来改去。

## 5. 选择来源与强制目标

| 选择来源 | 语义 | 机制 |
|---|---|---|
| 玩家选择 | 响应窗口内给出候选集，等 ServerRPC 提交（`10`/`11`） | `选择输入` 统一入口 |
| 规则自动 | 锁定技/被动自动选（唯一候选/无选择权） | `ResolveTargets` 直接出结果 |
| 半自动 | 有默认目标可改 | 先自动后给确认窗口 |

> 目标描述里的 `bForceSelection` + `Pool` 已能表达"必杀技自动锁定唯一存活者"；玩家的临时"我要打他"是**同一裁决**，差别只在选择输入通道。

## 6. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `04`：交易携带 `TargetSpec`（或已锁定的 `TargetSet`） | 交易 Execute 前完成锁定；效果对锁定集执行 |
| 对 `09`：技能声明含目标描述 | 激活时 `ResolveTargets` 决定监听者/结算对象 |
| 对 `10`：窗口提供候选与提交 | 响应内容 = 从候选提交一个目标子集 |
| 对 `07`：无目标使用/有目标使用 | 频率计数与目标裁决互不感知，只管次数 |

## 7. 扩展点

- 新对象种类可被目标化 → 实现 `Targetable` 接口 + 注册候选池/校验器，裁决主流程不改。
- 新距离模型（如"距离按场次牌堆长度算"）→ 换 `ISeatLayout` 实现，交易与技能代码不动。
- 新目标约束 → 数据组合校验器，或内容侧新校验器注册。

## 8. 落地与状态

> 本卷为**待落地**模型（此前架构无目标/距离抽象）：随 P6「技能·目标·频率」与 P5 案例验证实现。建议放 `Battle/Toolkits/` 或独立 `Targeting/` 目录，接口与校验器同库，纯语义无复制。

## 9. 案例（仅作样本，不进框架）

- 攻击距离受限的"杀"：目标描述 = 存活敌方 + 距离校验器(≤ 当前攻击范围)。武器技只注册一条 `IRangeModifierProvider` 修正。案例用途：验证目标与距离解耦。
- "弃一张牌指定自己"（增益类）：身份校验器(自己)。案例用途：校验器组合。
- "全场各选一张"（AOE 类）：候选池=全员、max 随人数、对每人的牌再区域校验。案例用途：目标集泛化为区域牌。
- 判定牌（"先放置、后结算"牌类）：目标描述 = 存活的其他角色 + 占用校验（目标判定区未含同种）；当全员判定区均已含同种时无合法目标 → 不出使用入口。案例用途：验证使用门槛与区域占用类目标过滤。
