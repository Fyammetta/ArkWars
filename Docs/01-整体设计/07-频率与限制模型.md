# 07 频率与限制模型

> 把"每回合一次""整局两次""摸牌阶段限一次""觉醒后+1""出牌阶段能出几张"收进同一个**频率账本**，避免各处散落"我记个数"。
> 语义层无状态裁决的一部分：账本负责**记录与裁决上限**，不关心是什么技能/什么阶段在消耗。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 计数键的定义、占用/释放、上限裁决 | 技能激活流程（`09`） |
| 重置时机的统一处理（回合开始/轮到己方/整局不重置） | 具体规则为何要限制（内容侧数据） |
| 全局/每角色/每技能/每卡牌维度的计数 | 冷却/状态表现（与 GAS Cooldown 正交，见 §6） |
| "一次机会"的校验（可先查后耗） | 撤销/回滚以外的异常补偿 |

## 2. 计数键命名空间（账本地址）

```
Scope（谁的名下） × 资源族（数什么） × 周期（何时清零）

示例：
  Round.DeployLimit.Actor.{id}        每回合可出牌数（全局规则可挂任何角色名下）
  Game.Skill.{SkillId}.{OwnerId}      某技能整局可用次数
  Round.Skill.{SkillId}.{OwnerId}      某技能每轮可用次数
  Phase.SkillExtra...                  某阶段内追加次数（如"出牌阶段限一次"+1）
```

计数键规范：
- 键是**标签/字符串组合**而非散落的 map key；用 `{作用对象} + {族} + {周期}` 三段式命名，便于统一查询与重置。
- 上限来自**数据声明**（技能表/规则表的 `MaxUses` 字段），不在引擎写死。

## 3. 账本操作（唯一入口）

```cpp
class UFrequencyLedger                       // 每局一个，宿主=流程（服务器）
{
    bool QueryUseAllowed(const FGameplayTag& Key, int32 Cost = 1) const;  // 预检：不消耗
    bool TryConsume(const FGameplayTag& Key, int32 Cost = 1);             // 原子：够则扣并记录（校验在提交侧再走一次）
    void Release(const FGameplayTag& Key);                                // 回滚/补偿：交易取消/防止（04 §2 Finish(false)）的消耗退回；吞效果（bNullified，见 04）不退
    void ResetScope(EResetScope Scope);                                   // 按周期统一清零
    int32 GetUsed(const FGameplayTag& Key) const;                         // 已用次数（独立方法，签名与附录一致）
    int32 GetRemaining(const FGameplayTag& Key) const;                    // 剩余 = max(0, 上限 - used)
};
```

- **先查后耗 + 提交侧再校验**：窗口期把"询问是否发动"与"真正发动"分开，两处都查账本，防窗口内竞态超发。
- 消耗动作若被取消/防止（交易 `Finish(false)` / 响应链失败），调用 `Release` 退回——账本是结算回滚的账房，不是一次性递减器。出牌效果被吞（`bNullified`，见 `04` §4）**不回滚**：动作已发生、账本照记。
- 周期边界（轮到己方/回合开始/整局）由流程（`02`）发出"周期刷新"事实，账本订阅后统一 `ResetScope`；**不靠每个技能自己清自己**。

## 4. 数据侧接线（频率是技能声明的一部分）

技能声明（`09` §2 的 `FSkillInfo`）增三字段即可获得频率能力，引擎无感知：

```cpp
FGameplayTag FrequencyKey;     // 账本键族（如 Skill.X；为空=不计数）
int32 MaxUsesPerRound = 0;     // 每轮上限（0 = 不限，用于觉醒前/后）
int32 MaxUsesPerGame  = 0;     // 整局上限
bool  bPerOwner = true;        // 键挂自己名下（区分"每人各一次"与"全局共用一次"）
```

> 触发判定流程（`09`）在询问前查、激活时耗；觉醒/修改技（`09` §7）改的是**声明副本**的上限，账本键带演化代次，天然分开计数。

## 5. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `09`：激活条件之一 | 查询/消耗经 `FrequencyLedger` 统一入口 |
| 对 `02`：周期重置信号 | 回合边界广播 → 账本 ResetScope |
| 对 `04`：取消补偿 | 交易 `Finish(false)`（取消/防止）/响应失败 → 调用方 `Release` 退回；吞效果（`bNullified`）照记不退 |
| 对 `10`：询问期预检 | "能否发动"在开问前查，发动时再耗 |

## 6. 与 GAS Cooldown 的边界

| 场景 | 用谁 |
|---|---|
| 一次技能内部的短暂硬冷却（如 1 秒） | GAS Cooldown GE（表现/禁按） |
| 回合制"每回合一次/每轮 N 次/整局两次" | **本卷账本**（周期与规则对齐） |
| 觉醒后次数变化 | 账本键换代次（`09` §7），Cooldown 不参与 |

两者正交：Cooldown 管"按时间不许用"，账本管"按回合制配额不许用"。别把回合数塞进 Cooldown 时长。

## 7. 扩展点

- 新频率规则 → 数据声明加上限 + 选键族；若键族语义新（如"每种花色各一次"），账本加一个键解析器注册，主流程不改。
- 回滚语义随交易防止路径（`04` §2 `Finish(false)`）自然生效，无需账本感知具体交易。

## 8. 落地与状态

> 待落地（P6）。落点建议：`Battle/System/FrequencyLedger.*`（UObject，挂流程子系统）或语义层纯结构；键解析器支持 `{Scope}×{族}×{周期}` 三段。

## 9. 案例（仅作样本，不进框架）

- 限定技"整局一次"：`MaxUsesPerGame=1`，用掉即空。
- 觉醒后"整局两次变为两次都可用，且每轮一次"：觉醒产生声明副本（`09`），账本新键开新计数。
- 发动后被取消/防止：交易 `Finish(false)` → `Release` 退回一次——"动作没发生不扣次数"。出牌被吞效果（`bNullified`）则**不退**：动作算发生了。

## 附：本卷类完整定义（目标形态）

> 汇编口径：以本卷设计为准，把 §2 键命名空间、§3 账本操作、§4 数据侧接线与 `02` 周期刷新事实合并为"完工后"完整定义。键与上限的类型按 §4 定稿（键 = `FGameplayTag`，上限 = 声明 `MaxUses*`）；UE 化落点（UObject 挂流程子系统）见 §8 与 P6 §3。

### EResetScope（§2 键的周期段 / §3 重置边界）

```cpp
// 账本键第一段"周期"（对应 §2 键示例 Round/Game/Phase 前缀）
enum class EResetScope : uint8
{
    Turn,    // 轮到己方（行动者边界）：己方回合/行动阶段进入事实 → 清零该周期键
    Round,   // 回合/轮边界：02 周期刷新事实（BroadcastRoundRefresh）→ ResetScope(Round)（P6 §3 接线）
    Phase,   // 阶段边界：出牌阶段限一次/追加类（键 Phase.*）随阶段进入清
    Game,    // 整局：不自动清零（仅对局开始时初始化归零）
};
```

### UFrequencyLedger（§3 账本，每局一个，宿主 = 流程/服务器；待落地 P6）

```cpp
class UFrequencyLedger
{
public:
    bool QueryUseAllowed(const FGameplayTag& Key, int32 Cost = 1) const;  // 预检：used + Cost <= 上限；不消耗，窗口开问前查（10）
    bool TryConsume(const FGameplayTag& Key, int32 Cost = 1);             // 原子：预检通过则 used += Cost 并返回 true（提交侧再走一次校验）
    void Release(const FGameplayTag& Key);                                 // 回滚最近一次消耗：交易取消/防止（04 §2 Finish(false)）/ 响应失败补偿；吞效果（bNullified，见 04）不退
    void ResetScope(EResetScope Scope);                                    // 周期清零：清空周期段 = Scope 的全部键（02 周期刷新事实驱动）
    int32 GetUsed(const FGameplayTag& Key) const;                          // 已用次数
    int32 GetRemaining(const FGameplayTag& Key) const;                     // 剩余 = max(0, 上限 - used)

private:
    // 账目：完整键 → 已用次数（键解析器把键切为 {周期}.{族}.{作用对象} 段；支持演化代次后缀，见 P6 §3）
    TMap<FGameplayTag, int32> UsedCounts;
    // 上限不驻留账本：按键的族段反查数据声明（09 §2：MaxUsesPerRound/MaxUsesPerGame/bPerOwner → 归属上限；0 = 不限，§4）
};
```

> 说明：
> - `Key` = 账本完整键，`{周期}.{族}.{作用对象}` 三段拼接的标签（§2 键示例），由键解析器构造/校验；`FrequencyKey`（`09` §2 的 `FSkillInfo`，`FGameplayTag`）是其中的"族"段。
> - 数据侧接线字段（`FrequencyKey`/`MaxUsesPerRound`/`MaxUsesPerGame`/`bPerOwner`，§4）属于技能声明（`09` §2 的 `FSkillInfo`）而非本卷类型，其完整定义见 `09` §2（`FSkillInfo` 完整定义），目标规则引用见 `05` 附录 `UTargetRuleData`。
