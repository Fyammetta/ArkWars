# 08 卡牌与容器模型

> 全游戏最高频的落子对象：牌怎么存、怎么搬、怎么被结算引用。移动从第一天就交易化（`04`），容器只提供区域读写接口，不解释意图。
> 落地：`ICardContainerInterface` + 玩家侧 `UCardManagementBusComponent` + 桌面侧 `ACardTableManager` + `FMoveMessage` DSL（`GameMessage.*`）。

## 1. 职责边界

| 管 | 不管 |
|---|---|
| 区域的定义、容器持有、保序、进出 | 移动的时机干预（查询窗口在 `03`，交易在 `04`） |
| 移动意图描述（DSL）与解析 | 出牌的响应链/费用（`10`/使用交易） |
| 区域 Tag → 容器的唯一解析 | 每张牌的具体规则（数据侧标签声明） |
| 牌的标识/合成（含虚拟牌） | 客户端表现（`11`） |

## 2. 区域归属约定（谁持有哪片区域）

| 区域 Tag（原生标签） | 宿主 | 字段 | 语义 |
|---|---|---|---|
| `Card.Area.Hand` | 玩家侧组件 | `HandCards` | 手牌 |
| `Card.Area.Equipment` | 玩家侧组件 | `EquipmentArea`（槽数组） | 装备/持久区 |
| `Card.Area.Judgement` | 玩家侧组件 | `JudgementArea`（每牌一槽） | 判定区（同种唯一、保进场时序；收单/结算形状见 §8） |
| `Card.Area.Pile` | 桌面 `ACardTableManager` | `PileArea` | 牌堆 |
| `Card.Area.Discard` | 桌面 | `DiscardArea` | 弃牌堆 |
| `Card.Area.Cache` | 桌面 | `CachedArea` | 缓存/移出游戏类 |
| `Card.Area.Used` | 桌面 | `PlayedArea` | 使用/缓冲堆 |

- 区域标签为**开放可扩展集**（新增"展示区/特殊区/专属区"按 `03` §3.2 的合规出路补标签 + 容器字段）。
- 新区域的两步接入：容器加字段与复制/OnRep + 注册进 §4 解析表。**引擎移动流程零改动**。

## 3. 容器接口（现状已固化）

```cpp
class ICardContainerInterface
{
    virtual void MoveIn(ICardContainerInterface* From,
        TArray<FGameplayTagContainer>&& Cards, const FString& Msg) = 0;
    virtual void MoveOut(ICardContainerInterface* To,
        const TArray<FGameplayTagContainer>& Cards, const FString& Msg) = 0;
    virtual TArray<FGameplayTagContainer> GetCardsByKey(const FGameplayTag& AreaKey) = 0;
    virtual TArray<FGameplayTag> GetAreaKeys() const = 0;
};
```

- 每侧容器只改**自己名下的区域**；`Msg` 携带意图原文（供自身按 `_To/_From` 决定入哪个区、是否走 `_bDiscard` 语义）。
- 卡在区内的身份标识：当前以 `FGameplayTagContainer`（牌 = 标签组合：种类/花色/点数 + 实例唯一 id 标签）表示；详见 §7 牌模型。
- 复制：区域属性全量 `DOREPLIFETIME` + 各区域独立 OnRep（客户端可分辨哪区变了）。

## 4. 区域解析（唯一入口）

```
ICardContainerInterface* ResolveContainer(APlayerState* Owner, const FGameplayTag& Area)
  玩家区域(Hand/Equipment/Judgement) → Owner->FindComponentByClass<UCardManagementBusComponent>()
  桌面区域(Pile/Discard/Cache/Used/…) → ACardTableManager::Get(World)
```

- 放 `BattleFunctionLibrary` 或流程子系统，**全局只有这一处**做"区域 → 容器"映射；交易/阶段体/技能一律经它，杜绝散落判断。
- `Owner/Target` 为空的归属规则（桌面到桌面、无主摸牌）在此统一约定。

## 5. 移动意图 DSL（`FMoveMessage`）

`CardMsgDef` 的 DSL 保留为**交易的输入描述**（交易的意图载体，见 `04`），解析器已随 P0 修复；完整 DSL 表在路线图 P2 §测试表：

| 片段 | 含义 |
|---|---|
| `NUM=n` | 数量（默认 1） |
| `FROM=区域码 / TO=区域码` | 源/目标区（`-AP/-AH/-AD/-AE/-AJ/-AS...`，含用户缩写映射） |
| `AREA=Skill.Foresee` | 特殊/技能专属区目标 |
| `CONDITION:SUIT=/H`、`MIN/MAX`、`PREDICATE` | 过滤条件（选中哪些牌） |
| `ORDER=Top/Random/Bottom` | 取牌顺序 |
| `DISCARD=1`、`IsDiscard` 键 | 显式弃牌标记（决定是否触发弃牌事件） |
| `_Meta` | 原文保留（容器落子/日志/回放用） |

修复纪律（P2 复核结论保留）：解析判真一律 `Find(...) != INDEX_NONE`；值解析不复用上一个键的残留 `Temp`。

## 6. 移动的查询与通知（对齐 `03`）

```
意图(FMoveMessage) → UCardMoveTransaction（04）
  → 查询时机 Card.Move（可改数量/去向/取消）         —— 通常无人响应，窗口空转成本可忽略
  → Execute：源 MoveOut + 目标 MoveIn（本卷接口）
  → 通知：Notify.Card.Moved；细分 AreaEntered/AreaLeft 供"装备入场"类技能订阅
```

- **弃牌过滤**：批量弃入 `Used`（缓冲堆）的结算末尾移动标注 `bConsiderAsDiscard`（字段已存在于 `FMoveMessage`），时机层据此过滤，避免"弃一张触发一次弃牌事件"。
- `_From == _To`（整理手牌）直接 SetCardOrder，不走 MoveOut/MoveIn。

## 7. 牌模型（标签组合 + 实例化）

- **牌 = 数据行 + 标签组合**：`FConvertedCard/FHandCardInfo` 提供种类/花色/点数/图面/语音数据；运行期实例用标签（`Card.Xxx`）表达其"可见身份"，实例唯一 id 防重复引用。
- **虚拟牌/效果产物**：不占用实体卡时（转化使用、视为某牌）用"临时标签组合 + 来源链"（`06` 来源追溯）建模，虚拟对象不落实体容器、不复制。
- 需要"角色牌/限定牌进手"等概念时走相同模型：区域任意 + 数据行类型化，**不进引擎特判**。
- **稳定分组身份 = 分类注册表声明**：牌需归属稳定分组（如"伤害类"，供状态做"禁止使用/打出某组牌"类封锁，`06` §2.3）时，以**分组注册表**登记，查询统一 `表.Contain(种类)`；分组不靠标签推导——开放标签只表达特征，分组表达归属，引擎判断一律查表。

## 8. 判定区：收单约束与结算形状（抽象）

判定牌是"先放置、后延结算"的牌类通用形状：经使用裁决后进入某角色的判定区，到该角色判定阶段统一结算。区域层不解释判定意图（§1 边界不变），但判定区携带两类**结构性不变量**，收单方、结算体、转移路径据此编程，互不重复判断：

### 8.1 区域不变量

- **同种唯一**：判定区对每种判定牌至多容纳一张。这是区域级数据约束，不是某张判定牌的个性规则；任何新判定种类自动继承。
- **保进场时序**：每次收单记录进场序号；结算顺序由此导出（见 §8.3）。

### 8.2 收单（进入判定区）

- **正常使用路径**：目标合法性裁决（`05` §3.2）已把"目标判定区已含同种"者过滤掉，落位即视为合法。区域/收单侧只执行落子与不变量维护，不做"拒收"语义。
- **转移路径**（判定结果驱动的牌位交接，如移交相邻座次）：若落点已含同种，一律顺延下一座次，直至空位；由同种唯一保证顺延必然收敛。不存在"放置失败"终局——转移要么落位，要么整条因无空位而由发起方裁决取消。
- 复制/表现：判定区内容与进场序号随区域属性复制（§3、`11`），客户端无写入路径。

### 8.3 结算（判定阶段）

- 判定区所有判定牌统一在持有者判定阶段结算（`02`）；顺序 = **后入先判（LIFO，按进场序号倒序）**。
- 判定阶段体只按 LIFO 逐张驱动"亮出判定牌（取牌堆顶）+ 读结果 + 离区"三步（施工见 P5）；每张的**离区方向与结果效果**（伤害/状态/转移）由判定结果的效果描述符决定（`06`），阶段体与容器不做判定牌特判。
- 转移只可能由判定结果驱动；不存在"收单失败即转移"规则（§8.2 已保证正常路径与转移路径都无放置失败）。
- **离区默认去向 = 弃牌堆**：结算后未走转移的判定牌由判定区移入弃牌堆（移动交易），并以**判定者（该判定区持有者，即本张判定的执行玩家）**为弃置来源广播通用弃牌事件（`03`/`04` 弃牌语义，视为判定者弃置一张牌）；转移类结果则改为移动交易接力到目标判定区，不广播弃牌事件。
- 亮出与结果对全桌公开，属事实通知通道（`03` 的 `Revealed` 族），不开"防"的查询窗口。

## 9. 与邻卷契约

| 本卷对外 | 契约 |
|---|---|
| 对 `04`：交易经容器接口落子 | `ResolveContainer` 单点解析 |
| 对 `03`：移动通知细分 | 区域进出挂技能的事实订阅点 |
| 对 `10`：出牌流程 | 使用 = 移动交易（到手→Used/结算区）+ 使用类查询时机 |
| 对 `11`：复制 | 区域属性 + 独立 OnRep；客户端无任何移动决策 |

## 10. 扩展点

- 新区域 → 加容器字段 + 解析表行 + 复制注册（三处，均在数据/注册面）。
- 新移动语义（如"置于牌堆顶/底、插入指定位置"）→ 容器接口加定位参数或 SetCardOrder，交易复用。
- 新牌类型 → 数据行 + 标签，引擎无改动。

## 11. 案例（仅作样本，不进框架）

- 摸牌阶段摸 N：阶段体薄层 → `FMoveMessage("NUM=n FROM=-AP TO=-AH")` 交易。
- 判定：判定阶段按判定区进场时序 LIFO 逐张结算（§8）：每张先亮出牌堆顶（落入判定区临时位）→ 读花色/点数结果 → 判定牌按结果离区（无转移 → 进弃牌堆，以判定者为来源广播弃牌事件；转移 → 落到下一座次判定区）——所有移动全走同一交易。
- "视作使用了一张牌"：虚拟牌标签组合 + 使用交易，不消耗实体牌。
