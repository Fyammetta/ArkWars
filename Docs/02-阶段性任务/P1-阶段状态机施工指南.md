# P1 施工指南：阶段状态机

> 对应整体卷：`01-整体设计/02-回合与阶段流程`（并承接 `P0` §3 分派项）。
> 目标：`UBattleGameFlowSubsystem` 真正驱动回合流转——一局自动走完全部阶段并正确轮转玩家。
> **实施状态：✅ 主体已实现（2026-09-07 复核）；本节列出已交付与剩余收尾。**

## 1. 范围

| 做 | 不做 |
|---|---|
| 回合 FSM、轮转、阶段修正队列裁决 | 接时机窗口（P3）；阶段体规则（P2 起薄层接入） |
| 阶段/顺位的复制与事实广播 | 客户端 UI（只消费复制与委托） |

## 2. 关键设计（卷 `02` 结论摘要）

- 阶段 = 同步状态机；`SetPhase` 是**事实**（广播 + 复制），只在服务器调用（`HasAuthority` 守卫保留）。
- 三档后缀语义固定：`_Pre/_Post` 是查询时机点（P3 接窗口）；主阶段是停留点（等待驱动）。
- 轮转：`Finish → SetNextPlayerActive() → Begin`；`GameStart` 只作中转。
- 修正队列 FIFO：`Skip` 吞段、`Extra` 顺延、`Jump` 立即（卷 `02` §4）。P1 只保最简正确 + 公共接口，塞修正的通道（窗口响应）属 P3。

## 3. 已交付（代码侧核对）

| 零件 | 说明 |
|---|---|
| `UGamePhaseManagerComponent` | 挂 GameState；`CurrentPhase/PlayersInOrder/ActivePlayerIndex` 复制 + OnRep；`SetPhase/SetNextPlayerActive/GetActivePlayer` |
| `GetPhaseManager()` | 子系统统一入口（走 GameState），不再摸 GameMode |
| `InitPlayerOrder` / `InitPlayers` | 填 `PlayersInOrder` + 起始位（`IsRunningOnServer()` 守卫） |

| 修正 Key | `FPhaseMessage`（`GameMessage.h`）已预留 |

## 4. 收尾清单（承接 P0 §3 分派，P1 剩余）

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| 1 | `SetPhase` 换人路径 | `FinishedPlayerIndex.Add(ActivePlayerIndex++)` 末位越界（== 玩家数且不回绕）；服务器侧不自广播 `OnActivePlayerChanged` | 一轮结束后回绕/重置 `ActivePlayerIndex`，或统一在 `BroadcastRoundRefresh` 换人 |
| 2 | `InitPlayers` | `Start %= Num()` 空数组除零；找不到 Commander 时 `ActivePlayerIndex` 保持 `INDEX_NONE` | 空数组提前 `return`；无 Commander 回退到 `Start` |

## 5. 验收

1. 手动逐步：服务器侧调试入口推 `""`（空=推进一步），日志目送 `Begin → … → Finish →（换人）Begin`，`ActivePlayerIndex` 每轮 +1 且客户端 OnRep 收到。
2. 自动巡转：临时 `FTimerHandle` 每秒 `Advance`，整局不间断轮转、换人正确；验毕拆除。
3. 修正冒烟：塞一条 `Skip`/`Jump`，确认跳过一个阶段 / 直达目标阶段。
4. 末位玩家 Finish 后正确回绕到首位（收尾 #1 的回归）。
5. 日志英文（`LogGamePlay`），阶段名取自 `GetPhaseTag`。

## 6. 边界（本阶段不碰）

- ❌ 响应窗口/AbilityTask/GameplayEvent——P3。
- ❌ 阶段体规则（摸几张、弃牌上限、判定区遍历）——P2 起的薄层。
- ❌ 客户端 UI / 表现——只消费复制与委托。
- ❌ `Event.Timing.*` 广播——P3。
