## 3. 施工内容

### 3.2 窗口生命周期实现（`03` §4 → `10` §2/§4）

```cpp
struct FResponderEntry { UBattleTransaction* Tx; int32 Priority; TObjectPtr<APlayerState> Owner; FGameplayTag SkillTag; };
struct FResponseWindow {
    FGameplayTag TimingTag;
    TObjectPtr<UBattleTransaction> Ref;          // 负载：交易引用（可空=纯阶段时机）
    TArray<FResponderEntry> Responders;          // 开窗时由时机索引+合法校验填出
    EWindowPolicy Policy; float Timeout;
};
```

- **开窗者只有一个入口**（`OpenTimingWindow(Tag, Ref, Policy)`，放流程子系统或独立窗口管理器），阶段机与交易驱动共用；杜绝第二套窗口实现。
- 关窗 = 汇总结果回写（修改交易字段 / 写入 `PendingModifiers`）→ 回调（阶段机 `Advance` 续走 或 交易 `OnWindowClosed`）。任何路径不悬挂。

### 3.3 响应的发现与询问（`03` §5、`10` §2/§5）

- `USkillManagerSubsystem` 建**时机 → 监听技能**索引；开窗查表填 `Responders`。
- 逐技能"合法预检"（来源在场/可用/账本余量——账本 P6 前先跳过或常量校验），排序 = `ResponsePriority` 降序 × 座次。
- `InOrder` 最小策略：按序逐人问；响应 or 放弃 → 下一位；全员弃/超时 → 空结果关窗。
- 询问内容 = 给窗口，服务端状态 `State.Responding` 上锁（阻断无关输入）；关窗撤锁。客户端只收"你有响应权 + 候选"，经 ServerRPC 提交，服务端**二次校验**（在 Responders 名单内 + 锁内 + 提交内容合法）。

### 3.4 两个接线点（改动极小、是 P3 的全部引擎 diff）

```
① 02 §3.2：Advance 遇 _Pre/_Post → OpenTimingWindow(该点时机) → 等关窗回调 → Advance()
   （关窗回调里把响应结果（Skip/Extra/Jump）写 PendingModifiers → 再 Advance，修正裁决照旧）
② 04 §3.2：DriveTransaction 内 Active->Execute();   ← 唯一一行
                            改为 Active->QueryTimings();  // 开窗即返、不清 ActiveTransaction（忙锁继续）
   QueryTimings()（P2 空占位 → 填）：逐个开 Ref=this 的查询时机（如 Card.Move）
   OnWindowClosed()：汇总 → 被防止/无效 → Cancel()；否则 Execute()
```

- 交易自身零改动：P2 的 `Finish/Cancel` 自收尾 + 回调踢链直接复用。
- 阶段机侧：技能响应（如"判定前跳过"）需在窗口关闭后**先应用修正再推进**，顺序约定写在 `03` §4 与 `02` §3。

### 3.5 超时与安全

- 每窗带 `Timeout`：到点按"全员放弃"收敛（`WaitDelay` 类兜底），日志告警 + 关窗继续——绝不让回合卡死在窗上。
- 无人响应的窗口（绝大多数移动）成本 = 查索引空表 → 立即关窗，无延迟路径。
- 所有开窗/收响应仅服务器（`IsRunningOnServer` 门控贯穿）。

### 3.6 技能体侧（`09` §3/§5 最小形态）

- 首批两条测试技能（内容侧，仅验证形状）：
  1. `bAskFirst=false` 自动技，监听 `Event.Notify.Card.Moved`——验证事实订阅；
  2. `bAskFirst=true` 主动技，监听 `Judgement_Pre`，响应后把 `Skip(Judgement)` 写入修正队列——验证"干预生效 + 阶段机续走"。
- 若后续验证需要"技能在窗口内异步做动作再响应"（如先摸一张再决定），引入 `UAbilityTask_WaitResponses`（服务器等待类），开窗结构不变，只新增等待载体——本阶段不做，留 P6。

## 4. 验收

1. 测试技能②：进入判定阶段前弹出窗口 → 触发跳过 → 序列从 Draw_Pre 继续（客户端复制同步）。
2. 交易窗口：一条移动交易开 `Card.Move`，测试监听技能把 `_Count 2→1`，落子后实际只移 1 张（验证窗口可改交易字段）。
3. 忙锁：窗口悬停期间再入队交易不重入；关窗后依次结算。
4. 超时：开一窗不响应，`Timeout` 后自动收敛，回合不卡死。
5. 响应锁：窗口期无关输入被拒；关窗后恢复。
6. 事实侧回归：自动技订阅 `Moved` 正常收到；`SetPhase` 委托照常（证明通知/查询两通道互不干扰）。
7. 无悬挂：日志无"窗口未关"告警；全量跑 P2 回归不破。

## 5. 边界（不碰）

- ❌ 响应链嵌套/抵消类完整交互与失效传播——P7（本阶段单层窗口）。
- ❌ 目标选择完整交互——P5/P6（P3 窗口先支持"是否响应/放弃"二元）。
- ❌ 数值伤害与濒死——P4/P5。
- ❌ 频率账本接入——P6（预检暂常量放行，占位注释标注）。
- ❌ 客户端窗口 UI——协议定形（候选下发/提交），表现 P7。
