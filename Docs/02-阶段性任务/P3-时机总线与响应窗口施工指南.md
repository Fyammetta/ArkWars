### 3.2 窗口生命周期实现（`03` §4 → `10` §2/§4）

```cpp
// 窗口内一条可响应项：开窗时由时机索引（03 §5）+ 合法预检产出（与 03 附录 FResponderEntry 逐字一致）
struct FResponderEntry
{
    UBattleTransaction* Tx;            // 关联交易（窗口负载；纯阶段时机可空）
    int32 Priority;                    // 本窗内响应次序（09 ResponsePriority；同值按座次稳定序，10 §2）
    TObjectPtr<APlayerState> Owner;    // 响应者所属玩家
    FGameplayTag SkillTag;             // 响应者技能标识（时机索引的键值来源）
};

// 窗口基座（与 03 §4/附录 FResponseWindow 一致；EWindowPolicy 不在此形状内，走 OpenTimingWindow 参数，见 10 §2）
struct FResponseWindow
{
    FGameplayTag TimingTag;              // 本次窗口对应的查询时机（Event.Timing.*，03 §3.1）
    TObjectPtr<UBattleTransaction> Tx;   // 关联交易（可空：纯阶段时机，如 Phase.*.Pre）
    TArray<FResponderEntry> Responders;  // 合法响应者名单（开窗时由时机索引 + 合法预检填出）
    float Timeout;                       // 超时兜底（秒）
};
```

- **开窗者只有一个入口**（`OpenTimingWindow(TimingTag, Tx, Policy)`，放流程子系统或独立窗口管理器；`Tx` 即窗口负载成员、`Policy` 为 `10` §2 策略参数），阶段机与交易驱动共用；杜绝第二套窗口实现。
- 关窗 = 汇总结果回写（修改交易字段 / 写入 `PendingModifiers`）→ 回调（阶段机 `Advance` 续走 或 交易 `OnWindowClosed`）。任何路径不悬挂。

### 3.3 响应的发现与询问（`03` §5、`10` §2/§5）

- `USkillManagerSubsystem` 建**时机 → 监听技能**索引；开窗查表填 `Responders`。
- 逐技能"合法预检"（来源在场/可用/账本余量——账本 P6 前先跳过或常量校验），排序 = `ResponsePriority` 降序 × 座次。
- `InOrder` 最小策略：按序逐人问；响应 or 放弃 → 下一位；全员弃/超时 → 空结果关窗。
- 询问内容 = 给窗口，服务端状态 `State.Responding` 上锁（阻断无关输入）；关窗撤锁。客户端只收"你有响应权 + 候选"，经 ServerRPC 提交，服务端**二次校验**（在 Responders 名单内 + 锁内 + 提交内容合法）。

### 3.4 两个接线点（改动极小、是 P3 的全部引擎 diff）

```
① 02 §3.2：Advance 遇 _Pre/_Post → OpenTimingWindow(该点时机) → 等关窗回调 → Advance()
   （关窗回调里把响应结果（Skip/Extra/Jump）写 PendingModifiers → 再 Advance，修正裁决照旧）
② 04 §3：DriveTransaction 内 Active->Drive();     ← 调用方不变（09-10 定案）
                    只需改基类 Drive() 体：Execute(); → QueryTimings();  // 开窗即返、不清 ActiveTransaction（忙锁继续）
   QueryTimings()（P2 置 Querying 占位 → P3 填）：逐个开 Tx = this 的查询时机（如 Card.Move）
   OnWindowClosed()（P2 空 → P3 填）：汇总响应结果 → 被防/无效 → Finish(false)（族钩子
   BroadcastFinish(false) 广播防止通知，不 Execute）；否则 Execute()（族自收尾 Finish(true/false)）
```

- 交易自身零改动：P2 就位的 `Finish(bool)` 唯一收尾（落 `Finished` → `BroadcastFinish(bool)` → `OnTransactionFinished` 踢链）直接复用；被防/无效不再是第二入口，只是 `Finish(false)` 的语义路径。
- 阶段机侧：技能响应（如"判定前跳过"）需在窗口关闭后**先应用修正再推进**，顺序约定写在 `03` §4 与 `02` §3。

### 3.5 超时与安全

- 每窗带 `Timeout`：到点按"全员放弃"收敛（`WaitDelay` 类兜底），日志告警 + 关窗继续——绝不让回合卡死在窗上。
- 无人响应的窗口（绝大多数移动）成本 = 查索引空表 → 立即关窗，无延迟路径。
- 所有开窗/收响应仅服务器（`IsRunningOnServer` 门控贯穿）。

### 3.6 技能体侧（`09` §3/§5 最小形态）

### 3.8 开窗通知链路与 `AppendModification`（`12` §4）

本阶段必须落地的"通知"四步（此前只有 §3.2 的形状、没有链路）：

1. `OpenTimingWindow` 内：查索引 → 合法预检 → 填 `Responders` → **广播 `FWindowOpened`**；
2. 询问：`State.Responding` 上锁 + 下发候选（§3.3）；
3. 响应者从窗口负载（= 交易引用）拿 `Tx` → `Tx->AppendModification(Req)`（交易侧唯一收口，
   `04` §4.1）→ **广播 `FTransactionModified`**；
4. `Close`：结果回写 → **广播 `FWindowClosed`** → 回调（阶段机 `Advance` / 交易 `OnWindowClosed`）。

> 现状缺口：`QueryTimings()` 只置 `Querying`、`AppendModification` 无调用者——**本阶段就是补这条链**。

### 3.9 交易嵌套入口（`04` §3.2，本阶段只留口）

- 字段：`NestedStack`（`TArray<FNestedTransactionFrame>`，定义见 `04` 附录 / `12` 附录 D）
  + `MaxNestedDepth`（默认 1，可配）落 `UBattleGameFlowSubsystem`；
- 入口：`PushNestedTransaction` / `PopNestedTransaction` + **拒绝分支**（超深 / 防环 / 非活动上下文）；

  （构造一次超深调用 → 告警且不改变 `ActiveTransaction`）；
- 决策点（本阶段定稿后回填 `04` §3.2）：子交易入队方式 —— `Start(bool bNested)` vs `EnqueueNested()`。

## 4. 验收

1. 测试技能②：进入判定阶段前弹出窗口 → 触发跳过 → 序列从 Draw_Pre 继续（客户端复制同步）。
2. 交易窗口：一条移动交易开 `Card.Move`，测试监听技能把 `_Count 2→1`，落子后实际只移 1 张（验证窗口可改交易字段）。
3. 忙锁：窗口悬停期间再入队交易不重入；关窗后依次结算。
4. 超时：开一窗不响应，`Timeout` 后自动收敛，回合不卡死。
5. 响应锁：窗口期无关输入被拒；关窗后恢复。
6. 事实侧回归：自动技订阅 `Moved` 正常收到；`SetPhase` 委托照常（证明通知/查询两通道互不干扰）。
7. 无悬挂：日志无"窗口未关"告警；全量跑 P2 回归不破。
8. 事件旁路：订阅 `FTransactionFinished` 的测试回调内抛错/耗时，交易与队列推进不受影响（`12` §7）。
9. 通知链路可观察：§4.2 的窗口修改在 `FTransactionModified` 有记录；开/关窗各有一条 `FWindowOpened/Closed`。
10. 嵌套入口：超深/非活动上下文的 `PushNestedTransaction` 被拒绝并告警，`ActiveTransaction` 不变。
