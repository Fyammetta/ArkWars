# P5 施工指南：濒死与判定流程

> 对应整体卷：`01-整体设计/04-交易模型`（濒死交易 + 嵌套插队）、`02`（判定阶段体薄层）、`08`（判定区移动）、`06`（阈值派生）、`03`（Dying 时机族）。
> 目标：① `Health ≤ 0` 的阈值派生真实的濒死流程——打断当前结算、逐人求回应、救回或死亡；② 判定阶段本体跑通（判定区四步移动走交易）。
> 本阶段**不做完整响应链/无懈类**（P7）、**不做复杂技能**（P6）。
> **实施状态：未开工。前置 = P4（生命属性 + 阈值钩子 + 伤害全链路）。**

## 1. 范围

| 做 | 不做 |
|---|---|
| `UDyingTransaction`：阈值触发、打断结算、救回/死亡两终局 | 死亡后的出局展示/翻面等表现细节（P7/内容侧） |
| 嵌套插队栈（濒死打断当前结算并归还） | 响应链嵌套/抵消（P7） |
| 判定阶段体薄层 + 判定区移动 | 判定改判/增判等技能（P6 起） |

## 2. 濒死流程（卷 `04` §2/§3 嵌套、卷 `06` §3 阈值、`03` §3.1 `Dying` 族）

### 2.1 触发与打断（嵌套插队实现点）

```
P4 阈值钩子（Health 到 0） → 创建 UDyingTransaction(Victim)
   → 嵌套插队：若当前有 ActiveTransaction（任何正在结算的交易）
       → 入嵌套栈（卷 04 §3 预留），濒死交易成为新的 Active 立即驱动
       → 濒死收敛后 → 出栈恢复被挂起交易（若其目标/前提已失效，按目标失效规则取消）
```

- 嵌套入口是 P3 忙锁上新增的**显式栈**：P3 未实现字段与入口（留作本阶段）。`PendingTransactions` 主队列不受影响。
- 多濒死同帧：栈式管理保证 LIFO 收敛，不产生乱序。

### 2.2 `UDyingTransaction` 骨架（卷 `04` §4 表格 + 卷 `03` §6 登记）

```cpp
UCLASS()
class ARKWARS_API UDyingTransaction : public UBattleTransaction
{
    GENERATED_BODY()
public:
    /* 其他成员（基类 §2 生命周期成员与 `04` §4.1 上下文/收敛形状，见 UBattleTransaction 头文件，不重复声明） */

    TWeakObjectPtr<APlayerState> Victim;
    int32 SaveProgress = 0;                 // 已累计回复量（何时脱离濒死由"Health>0"判）
    bool bSaved = false;
    virtual void Execute() override;        // 见下
};
```

- `QueryTimings()`：开 `Event.Timing.Dying` 窗口——**InOrder 逐人询问"救 / 放弃"**（卷 `10` §2/§10 案例）。
- `Execute()` 收敛逻辑：
  1. 每成功"救"响应 → 目标 `Health` 增加对应量（经卷 `06` 修改入口，来源 = 救助者，供追溯）；
  2. `Health > 0` → `bSaved=true`：`Finish(true)`（族 `BroadcastFinish(true)` 广播 `Event.Notify.Dying.Saved`）；
  3. 全放弃仍 ≤0 → 死亡结算：`Finish(true)`（族 `BroadcastFinish(true)` 广播 `Event.Notify.Dying.Resolved`——死亡口径），从存活集合移除/标记（具体淘汰动作 = 内容侧处理，引擎只到"濒死收敛 + 状态事实"）。
- 濒死期间禁止再触发重复濒死（锁：`State.Dying` 或账本式防重入）；同一目标同时多濒死由锁合并。

### 2.3 边界情形

- 濒死目标在窗口期被他人救/被加血脱离 → 本次濒死终止（`Finish(false)`，无行为、族广播 `Dying` 防止/取消类通知）。
- 濒死交易自身的"施救响应"中产生的任何新结算一律入主队列（`Enqueue`），不抢濒死栈；施救本体是窗口响应，不是交易。

## 3. 判定阶段体薄层（卷 `02` §3.3 + `08` §11 案例 + `08` §8 形状）

Judgement 阶段本体（阶段体注册表挂 `EGamePhase::Judgement` 的逻辑）。判定区带**同种唯一 + 进场时序**两个不变量（`08` §8.1）；阶段体只认区内现存牌，按进场时序 **LIFO**（后入先判）逐张：

```
对当前玩家判定区按进场序号倒序（LIFO）逐张：
 1) 牌堆顶 → 判定区：        UCardMoveTransaction("NUM=1 FROM=-AP TO=-AJ")（自动随机牌）
 2) 读取判定结果：            公开判定结果（区域属性复制已可见）；广播 Event.Notify.Judgement.Revealed
 3) 触发"判定结果"事件（事实订阅点；伤害/状态/转移等结果分支由内容侧挂判后效果——本阶段只留口）
 4) 判定区 → 弃牌堆：         UCardMoveTransaction("NUM=1 FROM=-AJ TO=-AD")
 每张间用现有"单条驱动+收尾踢"自然串行
```

- 判定是**事实驱动**而非开查询窗口（判定牌不可被"防"）；要"改判定结果/再判定"的技能（P6 内容侧）挂 `Revealed` 事实后的追加结算，不改本流程。
- 判定区同种唯一由**收单方与转移顺延**保证（`08` §8.2，收单合法性在 `05` §3.2）；阶段体不重复扫描、不做"拒收"语义。
- 判定牌（占槽牌）结算后进弃牌堆，并以**判定者（结算时判定区持有者）**为来源广播通用弃牌事件（`08` §8.3）；转移类结果的判定牌改为移动到目标判定区、不广播弃牌（P6 内容侧）。
- 判定区为空则本阶段空转直通（已是 P1 行为）。

## 4. 验收

1. 濒死触发：把一目标 `Health` 结算到 0 → 日志确认濒死交易打断当前流程（若存在其他活跃交易则嵌套入栈）。
2. 求回应：`Dying` 窗口 InOrder 逐人询问（空响应者名单时直接终局，不悬挂）。
3. 救回：某响应加血使 `Health>0` → `Saved` 通知；被挂起结算正确恢复。
4. 死亡：全员放弃 → `Resolved` 通知；目标移出存活；无二次濒死触发。
5. 判定流程：带多张判定牌进入 Judgment 阶段 → 按进场时序 LIFO 逐张结算（移动守恒符合 §3 流程，判定区同种唯一不变量成立）；`Revealed` 事实按序到达。
6. 回归：P2/P3/P4 全绿。

## 5. 边界（不碰）

- ❌ 完整响应链（抵消、多层询问）——P7。
- ❌ 多目标/技能目标规则与频率账本——P6。
- ❌ 死亡后的具体演出/结算扩展——内容侧（P7 表现口）。
- ❌ 判定后复杂效果——P6 起内容侧。
