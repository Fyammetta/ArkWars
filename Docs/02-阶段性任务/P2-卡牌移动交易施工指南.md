## 2. 行动项（施工顺序即依赖序）

### A. DSL 前置修复（`GameMessage.cpp`，卷 `08` §5 纪律）
1. `_bDiscard` 判真改 `Msg.Find(IsDiscard) != INDEX_NONE`（现 `&&` 直用返回值：无 DISCARD 时 `-1` 恒 truthy，以 `DISCARD` 开头时 `0` 反为 false）。
2. **独立解析 DISCARD 值**：不复用 `Temp`（读的是 NUM/FROM/TO 残留：含 FROM/TO 时是区域码，`Atoi` 恒 0），如 `FindKeyHelper{Msg,&T}(IsDiscard)` 后 `_bDiscard = Atoi(*T) != 0`。
3. 复核 `AREA=` 特殊区分支确走原生标签（`P0` §3 余留 1 的 P2 侧确认）。

### C. 交易基类与队列（卷 `04` §2/§3/§7）
- 生命周期方法落地：`Begin()`（校验 → Created → 入队）、`Execute()`（纯虚）、`Finish()`/`Cancel()`（统一落 `Finished`，`Finish` 走 Execute 后、`Cancel` 跳过，两者都回调管理器）；`QueryTimings/NotifyTimings/OnWindowClosed` 空占位。
- 驱动形态 **P2 即采用"单条驱动 + 收尾踢"**（与 P3 同构，P3 只改一行）：

```cpp
void EnqueueTransaction(Tx) { if(!Tx||!IsRunningOnServer())return; Pending.Add(Tx); DriveTransaction(); }
void DriveTransaction() { if(!IsRunningOnServer()||Active) return; if(Pending.IsEmpty())return;
    Active=Pending[0]; Pending.RemoveAt(0); Active->Execute(); }   // P3: Execute() → QueryTimings()
void OnTransactionFinished(Tx) { if(Active!=Tx)return; Active=nullptr; DriveTransaction(); }
```

- 忙锁语义：Execute 内新 Enqueue 只入队不驱动；收尾回调自然踢到下一条（"不递归、排队执行"，见卷 `04` §3）。
- 服务器门控 + `GetState()` 供调试。

### D. `UCardMoveTransaction`（卷 `04` §4）
- 补字段：`FMoveMessage Move; TArray<FGameplayTagContainer> Resolved;`；`Execute()` 移入 `.cpp` 实现：
  1. `ResolveContainer(Instigator, _From)` / `(Target, _To)` 双端解析；空则 `Cancel()`；
  2. `Candidates = From->GetCardsByKey(_From)` → `Resolved = Move(Candidates)`（复用 `FMoveMessage::operator()`：Predicate + Count + Order）；
  3. `From->MoveOut(To, Resolved, _Meta)` → `To->MoveIn(From, MoveTemp(Resolved), _Meta)` → `Finish()`；
  4. `_From == _To`（整理顺序）直调 `SetCardOrder`，不走 MoveOut/MoveIn。

### E. 两容器落子（卷 `08` §3）
- **玩家侧** `MoveIn/MoveOut` 补实现 + `HasAuthority` 门控：`_To/_From` 按 `CardTags::Hand/Equipment/Judgement` 分发；Equipment/Judgement 经 `FCardAreaSlotFactory::CreateEquipmentSlot(Key)` / `CreateJudgementSlot(Card)` 建槽，`FCardAreaSlot::Add/Remove` 落/取，槽容量约束。
- **桌面侧** `MoveIn/MoveOut` 按 `Pile/Discard/Cache/Used` 对应 `Append/Remove`（门控已有）。
- 区域字段已 `DOREPLIFETIME`，改完即同步；客户端零决策。

### F. `ResolveContainer`（卷 `08` §4）
- 唯一解析入口（放 `BattleFunctionLibrary` 或流程子系统）：玩家区（Hand/Equipment/Judgement）→ Owner 的 `UCardManagementBusComponent`；桌面区 → `ACardTableManager::Get(World)`；Owner 空归属规则在此统一。

### G. `StartGame` 发牌交易化（卷 `08` §11 案例）

## 4. 验收

1. 单步移动：调试入口发起 `UCardMoveTransaction`，日志 `[Move] From=X To=Y Num=N`，源区减、目标区加。
2. 全链路可见：客户端读复制区域前后数量一致。
3. DSL 回归：§3 用例表全过（含 `AREA=` 边界与 `_bDiscard`）。
4. 守恒对账：任意移动全局卡牌总数不变。
5. `StartGame` 开局后双方手牌 = 起始数、牌堆扣除正确。
6. 门控：客户端调用两容器 `MoveIn/MoveOut` 被忽略；日志英文、区域名取 `CardTags::*`。
