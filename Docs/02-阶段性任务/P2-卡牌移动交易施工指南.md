### C. 交易基类与队列（卷 `04` §2/§3/§7）
- 生命周期方法**已按 `04` §2 五态 + 单收尾重构落地**（09-08 复核代码确认，不再是施工目标）：`Start()` 非虚三层——① 服务器门控 → ② 调族钩子 `protected virtual bool Validate() const`（基类 `PURE_VIRTUAL`，族覆写做必填校验，失败拒绝入队、可修复后重试）→ ③ `State != Spawned` 防重入 + `Started` + `EnqueueTransaction(this)`；`Execute()` 为受保护纯虚（族实现、自收尾 `Finish(bool)`）；`Finish(bool bSuccess)` 是唯一收尾（落 `Finished` → 族钩子 `BroadcastFinish(bool)` → 子系统 `OnTransactionFinished` 踢链）；`QueryTimings()`（置 `Querying`）/`OnWindowClosed()`（空）为 P3 占位；`Begin`/`Cancel`/`bBegun`/`NotifyTimings` 已删净。本阶段只补族实现（§D）与队列驱动体，**不再碰生命周期**。
- **基类收敛三件随折叠载体定稿落地**（`04` §4.1/§4）：`EventTypes.h` 已定义折叠请求 `FTransactionModRequest`（`Operation`/`float Magnitude`/`Actor`/`Priority`）+ Op 集 `EModOp{Ignore, Add, Multiply, Clamp}`（09-08 收敛：减 = `Add` 负值、除 = `Multiply` 倒数）；基类 `protected TArray<FTransactionModRequest> ModeRequests` + 公开 `AppendModification(const FTransactionModRequest&)`（**已落地**：`State == Querying` 才收，P3 前无窗口 = 恒拒绝）+ 公开纯虚 `FoldMods()`（族必须实现：移动族无折叠 = 直通实现；伤害族 P4 给 `04` §4 三步折叠）。
- 驱动形态 **P2 即采用"单条驱动 + 收尾踢"**（与 P3 同构，P3 只改一行）：

```cpp
void EnqueueTransaction(Tx) { if(!Tx||!IsRunningOnServer())return; Pending.Add(Tx); DriveTransaction(); }
void DriveTransaction() { if(!IsRunningOnServer()||Active) return; if(Pending.IsEmpty())return;
    Active=Pending[0]; Pending.RemoveAt(0); Active->Execute(); }   // P3: Execute() → QueryTimings()
void OnTransactionFinished(Tx) { if(Active!=Tx)return; Active=nullptr; DriveTransaction(); }
```

- 忙锁语义：Execute 内新 Enqueue 只入队不驱动；收尾回调自然踢到下一条（"不递归、排队执行"，见卷 `04` §3）。
- 服务器门控 + `GetState()` 供调试。
- ⚠ 访问层级决策点：`Execute`/`QueryTimings`/`OnWindowClosed`/`Finish` 现为基类 `protected`，而驱动器（子系统 `DriveTransaction`）要调 `Execute`（P3 改调 `QueryTimings`）——P2 填驱动体时须先开放驱动入口（公开驱动段或经基类转发方法），并把方案回填本卷 §7 与 `04` §7。

### D. `UCardMoveTransaction`（卷 `04` §4）
- 族必填校验（卷 `04` §2/附录；基类 `Start` 已先调 `Validate()`，族只覆写）：覆写 `protected virtual bool Validate() const` —— `Message` 非空、`_From/_To` 已解析为有效原生标签；不满足返回 `false`（`Start` 拒绝入队、可修复后重试）。`ResolveContainer` 两跳区解析失败仍属 Execute 期兜底（走 `Finish(false)`），**不归** `Validate`。
- 字段现状：`TUniquePtr<FMoveMessage> Message`（`Create(Msg)` 已实现解析）；`TArray<FGameplayTagContainer> Cards` 为迁移残留（裸标签载荷，待桥接 `FArkCard` 或随 `Select` 收口删除，见卷 `08` §7.5）。`Execute()` 移入 `.cpp` 实现：
  1. `ResolveContainer(Instigator, _From)` / `(Target, _To)` 双端解析；空则 `Finish(false)`（族 `BroadcastFinish(false)` 广播移动失败/防止通知）；
  2. 源侧选中：`Ids = From->Select(_From, Msg)`（谓词/`NUM`/`ORDER` 过滤在容器 `Select` 内，谓词只读 `Tags`）；`_From == _To`（整理顺序）容器内直接改序（SetCardOrder），不发起跨区两跳；

  4. 跨区两跳返回后如无异常即收尾；`_bDiscard` 等弃牌标记由 `Msg` 携带到目标 `Add`（`GameMessage::FMoveMessage::_bDiscard` 字段已就绪，`08` §6 弃牌过滤）。

## 4. 验收

1. 单步移动：调试入口发起 `UCardMoveTransaction`，日志 `[Move] From=X To=Y Num=N`，源区减、目标区加。
2. 全链路可见：客户端读复制区域前后数量一致。
3. DSL 回归：§3 用例表全过（含 `AREA=` 边界与 `_bDiscard`）。
4. 守恒对账：任意移动全局卡牌总数不变。
5. `StartGame` 开局后双方手牌 = 起始数、牌堆扣除正确。
6. 门控：客户端调用两容器写接口（`Consume`/`Add`）被忽略；日志英文、区域名取 `CardTags::*`。

## 5. 边界（不碰）

- ❌ 阶段体规则（摸几张/弃牌上限/判定区遍历）——后续薄层。
- ❌ 伤害/濒死/出牌响应链——P4/P5/P7。
