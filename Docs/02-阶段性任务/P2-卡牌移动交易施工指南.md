```cpp
    if (!Tx) return;
    PendingTransactions.Add(Tx);               // Tx 真正入队
    if (ActiveTransaction.IsValid()) return;   // 忙锁排队：Execute 期新 Enqueue 只入队、不递归驱动
    DriveTransaction();
}
void UBattleGameFlowSubsystem::DriveTransaction() {
    if (!IsRunningOnServer()) return;
    if (PendingTransactions.IsEmpty()) return; // 空队列守卫
    ActiveTransaction = PendingTransactions[0];
    PendingTransactions.RemoveAt(0);
    ActiveTransaction->Drive();                // 驱动器唯一入口
}
void UBattleGameFlowSubsystem::OnTransactionFinished(UBattleTransaction* Tx) {
    if (!IsRunningOnServer()) return;
    if (ActiveTransaction != Tx) return;       // 收尾交易须为 Active，防串扰
    ActiveTransaction = nullptr;
    DriveTransaction();                        // 收尾踢链：自然驱动下一条
}
```

忙锁语义（卷 `04` §3）：`Execute` 内新 `Enqueue` 只入队不驱动；收尾回调踢下一条（"不递归、排队执行"）。

- **访问层级**：`Drive()` 非虚公开、`Execute()` 由 `public` 收回 `protected`（`CardMoveTransaction` 同步收拢）；`QueryTimings`/`OnWindowClosed`/`Finish`/`Validate`/`BroadcastFinish` 保持 `protected`——P3 开窗链只改 `Drive()` 体，调用方与入口名不变；`FoldMods()` 按 `04` §2 仍为公开族钩子。

约束（非行动项）：队列方法入口 `IsRunningOnServer()` 门控、客户端不驱动；`GetState()` 供调试。

### F. `ResolveContainer`（卷 `08` §4）

**状态：✅ 已完成。** 统一公共入口，类型链 `AActor*`。

- **公共入口**：`UBattleFunctionLibrary::ResolveContainer`（`Battle/Toolkits/BattleFunctionLibrary.h/.cpp`，非 `UFUNCTION`，与 `FilterCardBy*` 同为纯 C++ 静态入口）：

```cpp
ICardContainerInterface* UBattleFunctionLibrary::ResolveContainer(AActor* Owner, const FGameplayTag& Area)
{
	if (!Owner) return nullptr;                                  // 空归属 → 无容器
	if (Owner->Implements<UCardContainerInterface>())            // 自身优先
		return Cast<ICardContainerInterface>(Owner);

	// 后备：Owner 未实现接口时取名下容器组件；Area 有效则优先命中持有该区域的组件
	ICardContainerInterface* Fallback = nullptr;
	for (UActorComponent* Component : Owner->GetComponentsByInterface(UCardContainerInterface::StaticClass()))
		if (ICardContainerInterface* Container = Cast<ICardContainerInterface>(Component))
		{
			if (Area.IsValid() && Container->GetAreaKeys().Contains(Area)) return Container;
			if (!Fallback) Fallback = Container;
		}

	return Fallback;
}
```

## 8. 设计备忘：`FArkCard` 不承载归属（Owner）

- **议题**：是否给 `FArkCard` 增加 `Owner` 成员——进入玩家任意区域置当前玩家、进入弃牌区置 `nullptr`。
- **语义确认**："牌归谁 ≠ 牌在什么容器"成立——牌被使用后（落桌面 `Used` 缓冲堆）至真弃置前，仍应视为打出它的玩家的（`08` §7.6：`Used` 不算重置位，入 `Discard` 才终结）。
- **结论：引擎与数据结构不改**——`FArkCard` 不加 `Owner` 成员、区域条目不包 `{Card, Owner}`；需要该语义的技能自行实现记录。
  - 归属在玩家区 / 弃牌堆可由"所在容器宿主"推导（玩家区 = 持有者，`GetContainerActor`；弃牌堆无主 = 桌面容器），引擎已有单点（`08` §4）；
  - `FArkCard` 为值类型、区条目 / 交易载荷多拷贝，冗余归属位会引入陈旧副本风险，且易主 / 入弃的写入点会散落各效果；
  - "Used 期仍归打出者"属技能语义需求（如复活 / 回手还给出牌者、使用痕迹只随入弃清理）——由需要它的技能挂实例标记 / 来源自记录（`08` §7.6 终结类别、`06` 来源链），引擎只保留"入弃即终"的剥离位，不做全局归属特判。
- **落点**：本备忘不产生 P2 行动项（§E/F/G 不变）；若未来出现"所有者 ≠ 当前持有者"双轴（借调 / 驻场归原主）语义，再单独评审建模。
