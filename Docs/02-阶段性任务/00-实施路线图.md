## 2. 依赖关系

```
P0 ─ P1 ─ P2 ─ P3 ─┬─ P4 ─ P5
                    └─ P6 ─ P7
```

- **P2 是 P3 的地基**：交易队列"单条驱动 + 收尾踢"结构先行，
  P3 只在 `DriveTransaction` 里把 `Execute()` 换成 `QueryTimings()`。
- **P3 是分水岭**：P3 前全同步、不接窗口；P3 后干预点全部生效。
- **P4/P6 可并行**（P4 走数值、P6 走技能面），但建议 P4 先，让 P6 的技能体有真伤害可打。

## 4. 验收贯穿线（每个阶段都要能跑）

1. **阶段巡转**：一局从 `Begin` 走到下一位玩家 `Begin`，日志/复制全对。
2. **守恒对账**：全局卡牌总数不变（移动/使用守恒）。
3. **门控审计**：所有改状态入口有服务器门控；客户端零规则决策。
4. **回归**：旧功能不破（发牌、阶段委托、区域复制）。

每阶段文件 §验收 展开本线对应的具体检查。

## 5. 状态更新纪律

- 施工文件顶部"实施状态"行维护三态：`✅ 完成 / ⚠ 进行中 / 未开工`，并注明复核日期。
- 完成一个阶段：在 §检查表 打勾、回填本表状态、把遗留问题下放/归档，
  不在已关闭阶段里堆积开放项。
- 发现"需要改引擎/抽象形状"的问题 → 先回 `01` §6.3 评审再动工，禁止打补丁式加特判。
