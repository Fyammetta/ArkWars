# P3 架构图集：时机总线与响应窗口

> 配套 `P3-时机总线与响应窗口施工指南` 与整体卷 `02/03/04/10/12`，以**代码现状为准**（命名对齐 `EventTypes.h` / `BattleGameFlowSubsystem` / `BattleTransaction`）。
> 标记口径：✅ = 已落地；🚧 = P3 待建（索引/接线/RPC 协议）；⏭ = 留后续阶段（P5/P6/P7）。
> 关闭裁决口径（全图集统一）：**关闭时机统一只通过 UI 决定**——`FResponseWindow.Timeout` 是下发给 UI 的时间预算，倒计时到点 UI 直接请求关闭（与"放弃"同一 RPC 入口）；引擎侧不持有任何定时器（P3 §3.5）。

## 1. UML 类图（当前代码形状）

> 拆成两张：**1a 引擎与协作者**（行为主轴）、**1b 窗口数据形状**（静态骨架）。每张图节点少、声明顺序即层序（每条边恰好跨一层），同层绕行折线自然消失；连线一律 `stepAfter` 直角单拐。

## 2. 时序图 A：交易查询窗口全链路（✅ 已落地，验收 §4.2 的主干）

> `Start → 入队 → Drive → QueryTimings → OpenTimingWindow → 询问 → AppendModification → Close → OnWindowClosed → Execute → Finish → 踢链`

```mermaid
sequenceDiagram
    autonumber
    participant C as 创建方(技能/玩家)
    participant Tx as UCardMoveTransaction
    participant Flow as UBattleGameFlowSubsystem
    participant UI as 客户端UI(响应者)
    participant Obs as C面订阅者(旁路)

    C->>Tx: Create(Msg) + Start()
    Tx->>Tx: Validate() 且 State==Spawned
    Tx->>Flow: EnqueueTransaction(this)
    Flow->>Flow: PendingTransactions.Add(忙锁空则驱动)
    Flow->>Tx: Drive()
    Tx->>Tx: QueryTimings() → State=Querying
    Tx->>Flow: OpenTimingWindow(Card.PreMove, this, InOrder)
    Flow->>Flow: 门控IsRunningOnServer + 单层窗口保护
    Flow->>Flow: 前置 IsResponding() 检查(响应中→拒绝+日志·不触碰状态)
    Flow->>Flow: CollectResponders ①查索引②验活预检③排序(Priority降序×座次)✅
    Flow-->>Obs: FWindowOpened.Broadcast(Window)
    Note over Flow,Obs: 旁路纪律(12§7)：订阅者异常不影响推进

    alt 名单为空(绝大多数移动·无监听直通)
        Flow->>Flow: CloseTimingWindow() 零延迟(不上锁)
    else 有响应者(InOrder)
        Flow->>Flow: TryEnterResponseLock() 入锁(单一收口)
        Flow-->>Obs: FResponseLockChanged.Broadcast(true) 旁路
        loop 游标逐人·问完全员为止
            Flow->>UI: AskNextResponder 下发候选+Timeout预算🚧协议
            alt 行使响应权
                UI->>Flow: ServerRPC → SubmitWindowResponse(Responder, Req)
                Flow->>Flow: 二次校验：窗口在场+锁内+正被询问者
                Flow->>Tx: AppendModification(Req)
                Tx->>Tx: State==Querying才收 → ModeRequests.Add
                Tx-->>Obs: FTransactionModified.Broadcast(Tx, Req)
                Flow->>Flow: bAnyResponded=true·游标++
            else 放弃 或 UI倒计时到点(同一入口·详见时序B)
                UI->>Flow: ServerRPC → DeclineWindowResponse(Responder)
                Flow->>Flow: 同一套二次校验 → 不落任何账·游标++
            end
        end
    end

    Flow->>Flow: CloseTimingWindow：ExitResponseLock()撤锁→摘负载复位→(顺序关键)
    Flow-->>Obs: FResponseLockChanged.Broadcast(false) 旁路
    Flow-->>Obs: FWindowClosed.Broadcast(Window, bAnyResponded)
    Flow->>Tx: OnWindowClosed() (friend·C面直调)
    Tx->>Tx: 闸门State==Querying·问完全部时机 → TryExecute()
    Tx->>Tx: Validate失败→Finish(false)·FoldMods()一次性折叠(不按RPC到达序·预置牌不折叠)
    Tx->>Tx: Execute：Consume源区 + Add目标区 → Finish(bSuccess)
    Tx-->>Obs: BroadcastFinish → OnCardMoved(A面事实 Notify.Card.Moved)
    Tx->>Flow: OnTransactionFinished(this)
    Flow->>Flow: 校验==ActiveTransaction → 清忙锁 → DriveTransaction()下一条
```

## 3. 时序图 B：UI 裁决关窗（放弃 / 倒计时到点 = 直接请求关闭）

> 引擎侧无定时器；`Timeout` 只是 UI 的时间预算，到点由 UI 主动请求关闭（P3 §3.5）。

```mermaid
sequenceDiagram
    autonumber
    participant UI as 客户端UI(当前被询问者)
    participant Flow as UBattleGameFlowSubsystem
    participant Tx as UBattleTransaction
    participant Obs as C面订阅者(旁路)

    Note over Flow: 窗口悬停中·bRespondingLock=true·游标=i
    Flow->>UI: 候选已下发(附Timeout时间预算)

    alt 玩家点击放弃
        UI->>Flow: ServerRPC → DeclineWindowResponse(Responder)🚧协议
    else UI倒计时到点(超时=直接请求关闭)
        UI->>Flow: 同一RPC入口 → DeclineWindowResponse(Responder)
    else 无关输入(锁外/非当前被询问者)
        UI->>Flow: 任意提交
        Flow-->>UI: 二次校验拒绝(Warning日志·窗口不动)
    end

    Flow->>Flow: 校验：窗口在场+锁内+正被询问者
    Flow->>Flow: 不落任何修改·游标++ → AskNextResponder()

    alt 还有下一位
        Flow->>UI: 询问下一响应者
    else 全员弃
        Flow->>Flow: CloseTimingWindow() 空结果关窗
        Flow-->>Obs: FWindowClosed.Broadcast(Window, false)
        Flow->>Tx: OnWindowClosed() → Execute() 无修改原样落子
    end

    Note over Flow,UI: 已知边界：UI是唯一关闭裁决者——掉线/UI未接入时窗口悬停无服务端兜底(P7接UI时复核)
```
