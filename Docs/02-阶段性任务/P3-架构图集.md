# P3 架构图集：时机总线与响应窗口

> 配套 `P3-时机总线与响应窗口施工指南` 与整体卷 `02/03/04/10/12`，以**代码现状为准**（命名对齐 `EventTypes.h` / `BattleGameFlowSubsystem` / `BattleTransaction`）。
> 标记口径：✅ = 已落地；🚧 = P3 待建（索引/接线/RPC 协议）；⏭ = 留后续阶段（P5/P6/P7）。
> 关闭裁决口径（全图集统一）：**关闭时机统一只通过 UI 决定**——`FResponseWindow.Timeout` 是下发给 UI 的时间预算，倒计时到点 UI 直接请求关闭（与"放弃"同一 RPC 入口）；引擎侧不持有任何定时器（P3 §3.5）。

## 1. UML 类图（当前代码形状）

> 拆成两张：**1a 引擎与协作者**（行为主轴）、**1b 窗口数据形状**（静态骨架）。每张图节点少、声明顺序即层序（每条边恰好跨一层），同层绕行折线自然消失；连线一律 `stepAfter` 直角单拐。

### 1b 窗口数据形状（静态骨架）

> 前两个类是**锚点**（完整形状见 1a，此处只列被引用的成员）；声明顺序即层序，每条边恰好跨一层——没有同层边，也就没有绕行折线。

```mermaid
%%{init: {"flowchart": {"curve": "stepAfter"}}}%%
classDiagram
    direction LR

    class UBattleGameFlowSubsystem {
        <<锚点·完整形状见1a>>
        -TOptional~FResponseWindow~ ActiveWindow 单层窗口
    }

    class UBattleTransaction {
        <<锚点·完整形状见1a>>
        #EState State 状态机
        #TArray~FTransactionModRequest~ ModeRequests 修改请求集
    }

    class FResponseWindow {
        <<窗口基座 ✅>>
        +FGameplayTag Timing 查询时机
        +TStrongObjectPtr~UBattleTransaction~ Tx 负载·强持有防GC
        +TArray~FResponseEntry~ Responders 合法响应者名单
        +float Timeout 下发UI的时间预算
    }

    class FResponseEntry {
        <<名单条目 ✅>>
        +TStrongObjectPtr~UBattleTransaction~ Tx
        +int32 Priority 相对座次序快照(开窗现算·非技能数据)
        +TWeakObjectPtr~APlayerState~ Owner 响应者玩家
        +FGameplayTag Key 技能标识
    }

    class FTransactionModRequest {
        <<修改请求 ✅>>
        +EModOp Operation Ignore-Add-Multiply-Clamp
        +float Magnitude
        +TWeakObjectPtr~APlayerState~ Actor
        +int32 Priority
    }

    class EWindowPolicy {
        <<enumeration ✅>>
        All ⏭P7
        InOrder P3最小集
        FirstOnly ⏭P7
    }

    class EState {
        <<enumeration ✅>>
        Spawned
        Started
        Querying 窗内收修改的闸门
        Executed
        Finished
    }

    class APlayerState {
        <<响应者所属 ✅>>
    }

    UBattleGameFlowSubsystem o-- FResponseWindow : ActiveWindow单层
    UBattleGameFlowSubsystem --> EWindowPolicy : ActivePolicy·策略不进窗口形状
    FResponseWindow *-- FResponseEntry : Responders
    FResponseWindow --> UBattleTransaction : Tx负载·强持有防GC
    FResponseEntry --> APlayerState : Owner
    UBattleTransaction *-- EState
    UBattleTransaction o-- FTransactionModRequest : ModeRequests
```

## 2. 时序图 A：交易查询窗口全链路（✅ 已落地，验收 §4.2 的主干）

> `Start → 入队 → Drive → QueryTimings → OpenTimingWindow → 询问 → AppendModification → Close → OnWindowClosed → Execute → Finish → 踢链`

```mermaid
sequenceDiagram
    autonumber
    participant C as 创建方(技能/玩家)
    participant Tx as UCardMoveTransaction
    participant Flow as UBattleGameFlowSubsystem
    participant UI as 客户端UI(响应者)
    participant Obs as C面订阅者(旁路)

    C->>Tx: Create(Msg) + Start()
    Tx->>Tx: Validate() 且 State==Spawned
    Tx->>Flow: EnqueueTransaction(this)
    Flow->>Flow: PendingTransactions.Add(忙锁空则驱动)
    Flow->>Tx: Drive()
    Tx->>Tx: QueryTimings() → State=Querying
    Tx->>Flow: OpenTimingWindow(Card.PreMove, this, InOrder)
    Flow->>Flow: 门控IsRunningOnServer + 单层窗口保护
    Flow->>Flow: CollectResponders ①查索引②预检③排序🚧
    Flow-->>Obs: FWindowOpened.Broadcast(Window)
    Note over Flow,Obs: 旁路纪律(12§7)：订阅者异常不影响推进

    alt 名单为空(绝大多数移动·无监听直通)
        Flow->>Flow: CloseTimingWindow() 零延迟
    else 有响应者(InOrder)
        Flow->>Flow: bRespondingLock=true(State.Responding)
        loop 游标逐人·问完全员为止
            Flow->>UI: AskNextResponder 下发候选+Timeout预算🚧协议
            alt 行使响应权
                UI->>Flow: ServerRPC → SubmitWindowResponse(Responder, Req)
                Flow->>Flow: 二次校验：窗口在场+锁内+正被询问者
                Flow->>Tx: AppendModification(Req)
                Tx->>Tx: State==Querying才收 → ModeRequests.Add
                Tx-->>Obs: FTransactionModified.Broadcast(Tx, Req)
                Flow->>Flow: bAnyResponded=true·游标++
            else 放弃 或 UI倒计时到点(同一入口·详见时序B)
                UI->>Flow: ServerRPC → DeclineWindowResponse(Responder)
                Flow->>Flow: 同一套二次校验 → 不落任何账·游标++
            end
        end
    end

    Flow->>Flow: CloseTimingWindow：撤锁→摘负载复位→(顺序关键)
    Flow-->>Obs: FWindowClosed.Broadcast(Window, bAnyResponded)
    Flow->>Tx: OnWindowClosed() (friend·C面直调)
    Tx->>Tx: 闸门State==Querying → Execute()
    Tx->>Tx: FoldMods() 一次性折叠(不按RPC到达序)
    Tx->>Tx: Consume源区 + Add目标区 → Finish(bSuccess)
    Tx-->>Obs: BroadcastFinish → OnCardMoved(A面事实 Notify.Card.Moved)
    Tx->>Flow: OnTransactionFinished(this)
    Flow->>Flow: 校验==ActiveTransaction → 清忙锁 → DriveTransaction()下一条
```

## 3. 时序图 B：UI 裁决关窗（放弃 / 倒计时到点 = 直接请求关闭）

> 引擎侧无定时器；`Timeout` 只是 UI 的时间预算，到点由 UI 主动请求关闭（P3 §3.5）。

```mermaid
sequenceDiagram
    autonumber
    participant UI as 客户端UI(当前被询问者)
    participant Flow as UBattleGameFlowSubsystem
    participant Tx as UBattleTransaction
    participant Obs as C面订阅者(旁路)

    Note over Flow: 窗口悬停中·bRespondingLock=true·游标=i
    Flow->>UI: 候选已下发(附Timeout时间预算)

    alt 玩家点击放弃
        UI->>Flow: ServerRPC → DeclineWindowResponse(Responder)🚧协议
    else UI倒计时到点(超时=直接请求关闭)
        UI->>Flow: 同一RPC入口 → DeclineWindowResponse(Responder)
    else 无关输入(锁外/非当前被询问者)
        UI->>Flow: 任意提交
        Flow-->>UI: 二次校验拒绝(Warning日志·窗口不动)
    end

    Flow->>Flow: 校验：窗口在场+锁内+正被询问者
    Flow->>Flow: 不落任何修改·游标++ → AskNextResponder()

    alt 还有下一位
        Flow->>UI: 询问下一响应者
    else 全员弃
        Flow->>Flow: CloseTimingWindow() 空结果关窗
        Flow-->>Obs: FWindowClosed.Broadcast(Window, false)
        Flow->>Tx: OnWindowClosed() → Execute() 无修改原样落子
    end

    Note over Flow,UI: 已知边界：UI是唯一关闭裁决者——掉线/UI未接入时窗口悬停无服务端兜底(P7接UI时复核)
```

## 4. 时序图 C：阶段机 `_Pre/_Post` 时机窗（🚧 设计目标形态，`Advance` 接线待落）

> 纯阶段时机 `Tx = nullptr`；技能修正走 `PushPhaseResolvation`（PhaseMsgQueue），不经 ModRequest 通道。验收 §4.1"判定前跳过"。

```mermaid
sequenceDiagram
    autonumber
    participant Drv as 驱动方(阶段体/外部Advance)
    participant Flow as UBattleGameFlowSubsystem
    participant UI as 客户端UI(监听技能持有者)
    participant PS as UGamePhaseManagerComponent
    participant Obs as C面订阅者(旁路)

    Drv->>Flow: Advance()
    Flow->>Flow: Next=ResolveNextPhase(Current)
    Note over Flow: 🚧接线点(P3§3.4①)：Next为_Pre/_Post时<br/>不再直通，改为停窗

    Flow->>Flow: OpenTimingWindow(Phase.Judgment_Pre, nullptr, InOrder)
    Flow->>Flow: CollectResponders 查索引(测试技能②在名单)🚧
    Flow-->>Obs: FWindowOpened.Broadcast
    Flow->>UI: 上锁+下发候选(bAskFirst=true主动技)

    UI->>Flow: ServerRPC → SubmitWindowResponse(Responder, ...)
    Note over Flow: 纯阶段时机Tx为空——技能的修正不走AppendModification
    Flow->>Flow: 技能响应写入 PushPhaseResolvation("Skip(Judgment)")
    Flow->>Flow: CloseTimingWindow：撤锁→复位
    Flow-->>Obs: FWindowClosed.Broadcast

    Flow->>Flow: 回调路由：Tx为空 → Advance() 续走
    Flow->>Flow: ResolveNextPhase 消费PhaseMsgQueue(Skip整组吞掉Judgment_Pre/Judgment/Judgment_Post)
    Flow->>PS: SetPhase(Draw_Pre...) 事实广播+复制
    PS-->>Obs: FGamePhaseChangeDelegate(A面)
    Note over Flow,PS: 顺序约定：窗口关闭后先应用修正再推进(03§4/02§3)
```

## 5. 时序图 D：忙锁与事实通知面（窗口悬停期入队不重入 + A 面只读订阅）

> 验收 §4.3 忙锁 + §4.6 事实侧回归：查询/通知两通道互不干扰。

```mermaid
sequenceDiagram
    autonumber
    participant S1 as 技能A(移动交易发起方)
    participant S2 as 技能B(窗口悬停期入队方)
    participant Flow as UBattleGameFlowSubsystem
    participant Tx1 as Tx1(移动交易)
    participant Tx2 as Tx2(后到的交易)
    participant Auto as 自动技(bAskFirst=false·订阅Moved)

    S1->>Flow: EnqueueTransaction(Tx1)
    Flow->>Tx1: Drive → QueryTimings → 开窗
    Note over Flow: 窗口悬停：ActiveTransaction=Tx1不清(忙锁)<br/>bRespondingLock=true(State.Responding)

    S2->>Flow: EnqueueTransaction(Tx2)
    Flow->>Flow: ActiveTransaction有效 → 只入队不驱动(不重入)

    Flow->>Tx1: (UI裁决关窗)OnWindowClosed → Execute → Finish(true)
    Tx1-->>Auto: BroadcastFinish → OnCardMoved(Notify.Card.Moved)
    Note over Auto: A面事实=只读反应：不许否决、不许改负载<br/>订阅回调抛错不得影响推进(12§7)

    Tx1->>Flow: OnTransactionFinished(Tx1)
    Flow->>Flow: 清ActiveTransaction → DriveTransaction()
    Flow->>Tx2: Drive() 依次结算(窗口链重演)
```
