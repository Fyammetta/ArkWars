> 对应整体卷：`01-整体设计/06-状态与效果模型`（状态运行时）、`10-响应与交互模型`（响应链完整交互）、`11-网络与表现模型`（表现队列/Cue），并回填 `03` 对齐表与各卷案例。
> 目标：状态/持续效果有完整运行时；响应链闭环（嵌套/抵消/失效传播）；表现侧有最小但正确的"服务器事实 → 客户端演出"链路；整套引擎可支撑真实对局 alpha。

## 2. 状态运行时（卷 `06` §2.3/§3/§4）

- 状态 = 注册表条目 + 每目标状态实例：
  ```
  FStatusSpec（数据）：状态标签 / 生命期声明 / 层数上限与刷新策略 / 附加修改 / 互斥组
  FStatusInstance：Spec + 来源链 + 当前层数 + 到期计数
  ```
- 施加路径：效果提交 → 目标侧裁决（互斥替换/层数上限/刷新策略按 Spec 声明）→ 挂载 → 广播获得。
- 到期：回合边界统一 tick（每状态按 Spec 自减），到期卸载 + 广播失去；"至本局/至来源离场"由 Spec 生命期与来源链裁决。
- 状态事件登记 `03` 对齐表（获得/失去 = 事实；确需防止的口子经 `Timing` 族单点登记）。
- 来源失效（给状态的单位死亡/离场）：沿来源链进入结束处理（到期或归属转移规则）。

## 3. 持续效果执行（卷 `06` §2.2/§6）

- 一次性效果（P4 已有）外，补**持续效果**形态（按回合重复/时段生效）：携带来源与到期规则；每次触发走同一"效果提交 → 修改入口"，不新开通道。
- 若 GAS 案：状态以额外 GE 承载，到期 = 移除 GE；非 GAS 案用状态实例的附加修改段执行。两案行为对齐并写卷 `06` §6。

## 4. 响应链完整交互（卷 `10` §3/§5/§6）

- 链栈帧实现：每帧 = 一个窗口（记录响应者/内容/是抵消还是追加）；终止条件（无人响/链深上限/首个抵消成功）；**自底向上**收敛。
- 失效传播：链下层目标中途失效 → `05` 目标失效规则逐帧作废（向上传播）。
- 选择输入完备化：候选类型（目标/牌/元动作）+ 提交 → 服务端重算校验 → 回写；超时/断线按放弃收敛。
- "抵消链"就是链配置（谁是合法响应者、响应什么、能否再被响应），引擎只提供栈与配置，不识别具体应答名。

## 5. 表现最小闭环（卷 `11` §4/§9）

- 客户端表现队列：服务器事实/事件按序入队播放、无反向压力；队列满不阻塞服务器。
- GameplayCue 形态建立：伤害数字、状态获得/失去 Cue、判定翻牌——作为内容侧模板。
- 客户端交互（候选/你有响应权）按 `10` §5 协议渲染，提交 RPC 复用。

## 6. 回放/观战（可选，不阻塞 alpha）

- 以"交易队列 + 时机/通知事件"为指令流挂订阅器导出；录播/观战读流重放，不侵入结算（卷 `11` §7）。

## 8. 验收

1. 状态全生命周期：施加（含互斥/层数策略）→ 回合到期移除 → 获得/失去事实到 UI/Cue。
2. 持续效果按时段生效，来源失效按规则收尾。
3. 响应链：抵消用例（A 出 → B 抵 → C 再抵/A 目标中途失效）各路径收敛正确、无悬挂。
4. alpha 对局：任意复杂手顺跑完不卡死；守恒（牌数）与生命值一致；服务器权威无客户端写入。
5. 回放（若做）：导出流可完整复现。
6. 终态对账：路线图全勾、文档案例回填、无遗留"未分派"开放项。
