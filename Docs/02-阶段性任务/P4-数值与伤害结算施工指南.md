# P4 施工指南：数值与伤害结算

> 对应整体卷：`01-整体设计/06-状态与效果模型`（属性/效果）、`04-交易模型`（伤害交易）、`03`（伤害时机族）。
> 目标：角色拥有可改的生命值，伤害以"带伤害标签的数值修改"跑通全链路——`UDamageTransaction` 开 `Damage.Incoming/Dealt` 窗口 → 修改收敛 → 属性落值 → 通知与复制可见，含"防止/减免"分支。
> 本阶段**不做濒死**（`生命 ≤ 0` 只触发占位钩子，P5 接管）、**不做持续状态/复杂效果**（P7）。
> **实施状态：未开工。前置 = P3 全绿（窗口与交易收敛已闭环）。**

## 1. 决策项（动工前定，落卷 `06` §6）

**执行载体二选一**，接口与形状一致，后续卷不感知差异：
- A（推荐，若项目启用 GameplayAbilitySystem）：`UAttributeSet`(Health/MaxHealth) 挂 PlayerState 的 ASC；伤害用动态构造 GE + `SetByCaller` 数值。
- B（若未启用 GAS）：以自定义 `AttributeSet` 风格组件（复制 Health + 修改入口）实现同一形状；技能体侧到 P6 再定激活载体。
两案都必须遵守：**属性修改只经"效果提交"入口；来源追溯（谁打的）从第一天生效**（卷 `06` §2.1/§5）。

## 2. 属性承载（卷 `06` §2.1/§6）

- `Health / MaxHealth`（`FGameplayAttributeData` 或等价）：默认满血；`MaxHealth` 来自对局配置。
- 属性值复制到客户端（OnRep 供生命条/伤害数字），**仅服务器写**。
- Clamp 下限 0；触发**阈值钩子**：`Health 达到 0` 的瞬间广播"濒死信号"（P5 前仅 Log+占位委托，不产生行为）。

## 3. `UDamageTransaction`（基类 `04` §4.1 + 折叠 `04` §4 + 卷 `06` §3/§4）

字段关系（写死，杜绝"基类已有 `Instigator/Target` 还要再填一套"的漂移）：
- **承受者 = 基类 `Target`**，本族语境称 `Victim`：单目标阶段直接读基类 `Target`，**不另建字段**；P6 接多目标时再把族目标集扩出来（届时基类单 `Target` 退为主目标/代表目标）。
- **`Source`（伤害归因）默认 = 基类 `Instigator`**：`Execute` 开头做**归因回退**（`Source` 无效 → `Source = Instigator`），直伤无需重复填——基类 `Start` 非虚、不写任何族字段（`04` §2，族上下文一律族自收），不落在此处；仅**转移/间接伤害**由转移路径在创建时显式填 `Source`——例：A 受杀、发动技能转移给 C，则 `Instigator` = A（交易发起方）、`Source` = 出杀者（因果归因，`06` §5 来源链末端）、`Target`(Victim) = C。裁决（击杀归属/来源死亡/来源追溯）只读 `Source`，不读 `Instigator`。

```cpp
UCLASS()
class ARKWARS_API UDamageTransaction : public UBattleTransaction
{
    GENERATED_BODY()
public:
    /* 其他成员（基类 §2 生命周期成员与 `04` §4.1 上下文/收敛形状，见 UBattleTransaction 头文件，不重复声明） */

    // ── 族语义扩展（上下文与收敛形状在基类 `04` §4.1，不重复声明）────
    TWeakObjectPtr<APlayerState> Source;            // 伤害归因来源（默认 = 基类 Instigator；转移/间接伤害时显式覆盖）
    int32 BaseAmount = 0;                           // "底"：来源侧原始值（Execute 前不变，追溯/审计用）
    FGameplayTagContainer DamageTags;               // 类型标签（卡/技能/忽略护甲等；原生标签）

    // ── 结果位（本族 FoldMods() 按 `04` §4 公式折叠回填后提交）─────
    int32 Amount = 0;                               // 初始 = BaseAmount；折叠后 = 最终值（"瞬时的 current"）
    bool bIgnored = false;                          // 完全防止（Ignore 短路落地）
    virtual void Execute() override;                // 开头调本族 FoldMods()（归并基类 ModeRequests → 本族结果位）；结尾自收尾 Finish(bool)
protected:
    virtual void FoldMods() override;               // 族实现 `04` §4 三步折叠：Ignore 短路 → (Amount+ΣAdd)×ΠMultiply → Clamp 上限；回填后清空
};
```

`Execute()` 服务器主流程：

```cpp
// 0. 归因回退（族自收，`04` §2：基类非虚入口不写族字段）：`Source` 无效 → `Source = Instigator`（转移/间接伤害已在创建时显式填）
// 1. 折叠收敛（`04` §4）：开头调本族 FoldMods()（覆写实现三步折叠），归并基类 ModeRequests
//    → 回填 Amount/bIgnored 并清空（同步无窗口 = BaseAmount/false）
if (bIgnored || Amount <= 0) { Finish(false); return; } // 被防止不落子：族 BroadcastFinish(false) 广播 Event.Notify.Damage.Prevented
// 2. 构造"修改声明"（案 A：动态 GE + SetByCaller；案 B：等价结构）：
//    修改 = Health -= Amount；标签带 DamageTags + Instigator=Source（因果来源 = 本族 Source，`06` §5）
// 3. 应用 → 属性落值（含 Clamp）
Finish(true);   // 唯一收尾；族 BroadcastFinish(true) 广播 Event.Notify.Damage.Applied（Amount 修正后值、来源、承受者、类型）
```

- `Finish(false)` 在此的语义 = "被防止、未造成任何修改"，符合卷 `04` §2（不 Execute 的终局，**无 `Cancel` 第二入口**）；**防止≠空转**——族 `BroadcastFinish(false)` 已广播 `Prevented`，UI/语音有据可查。
- 目标侧"死亡/离场"未发生时正常应用；若窗口期目标死亡（跨窗竞态）→ 目标失效规则（卷 `05` §2）终止本次结算，走 `Finish(false)`。

## 4. 伤害时机族接线（登记卷 `03` §6）

| 时机/事件 | 通道 | 谁开 | 用途 |
|---|---|---|---|
| `Event.Timing.Damage.Incoming` | 查询窗口 | `QueryTimings()`（P4 实现） | 承受者侧减免/防止/转移 |
| `Event.Timing.Damage.Dealt` | 查询窗口 | 同上 | 来源侧加成/锁定（P6 批量） |
| `Event.Notify.Damage.Applied / Prevented` | 事实通知 | `Execute` 内广播 | UI 伤害数字、技能订阅（如"受伤后回状态"） |

伤害链与"减伤技"的关系 = 技能体挂 `Damage.Incoming` 窗口**追加修改请求**（`Ignore` 短路 / `Clamp` 封顶 / `Add` 加（负值 = 减）/`Multiply` 倍率——**无独立 Sub/Div Op**，减 = `Add` 负值、除 = `Multiply` 倒数；多修改收敛定序见 `04` §4）；**全引擎无伤害特判**（案例模板在卷 `06` §10、样板在 `09` §11）。

## 5. 验收

1. 测试技/调试入口：对一目标结算 `UDamageTransaction(Base=1)` → 目标 `Health -1`、通知 `Applied`、客户端生命条变化。
2. 减免：另一测试技挂 `Damage.Incoming` 追加修改请求（`Add(-1)`（减 1）或 `Clamp`（上限 1））→ 折叠后结算正确；`Ignore` 短路走防止路径（`Finish(false)`/`Prevented` 日志与通知）。
3. 来源追溯：`Applied` 通知携带 Source；从通知可回溯到发起者。
4. 阈值占位：`Health` 归 0 触发占位钩子（Log），不崩溃、不产生行为。
5. 复制：服务器数值与客户端 OnRep 一致；客户端无写入路径。
6. 回归：P2/P3 全绿（移动、窗口、忙锁不破）。

## 6. 边界（不碰）

- ❌ 濒死求回应/死亡淘汰/伤害后处理链——P5（阈值钩子占位）。
- ❌ 持续状态/GE 到期/层数——P7（P4 只应用"一次性即时修改"）。
- ❌ 复杂目标（多目标/目标规则）——P6。
- ❌ 治疗/流失等非伤害修改——P6/P7（本阶段先只通伤害一例，形状复用）。
