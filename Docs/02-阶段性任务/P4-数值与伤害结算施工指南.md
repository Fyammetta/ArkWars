# P4 施工指南：数值与伤害结算

> 对应整体卷：`01-整体设计/06-状态与效果模型`（属性/效果）、`04-交易模型`（伤害交易）、`03`（伤害时机族）。
> 目标：角色拥有可改的生命值，伤害以"带伤害标签的数值修改"跑通全链路——`UDamageTransaction` 开 `Damage.PreHurt/Dealt` 窗口 → 修改收敛 → **盾血分配** → 属性落值 → 通知与复制可见，含"防止/减免"分支。
> 本阶段**不做濒死**（`生命 ≤ 0` 只触发占位钩子，P5 接管）、**不做持续状态/复杂效果**（P7）。
> **实施状态：决策项已落定（2026-09-18，§1/§3.1），施工未开工。前置 = P3 全绿（窗口与交易收敛已闭环）。**

## 1. 决策项（已落定，登记卷 `06` §6）

**执行载体 = 案 A（GAS 满配）**，2026-09-18 落定：
- `UAttributeSet`（`Health/MaxHealth/Shield`）挂 PlayerState 的 `ASC`——`BattlePlayerState::Asc` 已在场（`BattlePlayerState.cpp:13`，真 GAS 组件、已开复制）；伤害用动态构造 GE + `SetByCaller` 数值。
- **配置面 = `UAbilitySystemSettings`**（`Settings/AbilitySystemSettings.{h,cpp}`）：`AttributeSetClass`（挂载的属性集类）+ `DamageEffectTemplate`（伤害 GE 模板，取用经 `GetDamageEffectTemplate()`）。
- **属性初始化 = 选角落定后 `SetNumericAttributeBase` 逐项灌入**，值取自 `FOperatorCardInfo`（`Toolkits/ArkWarOperatorTypes.h`）← `OperatorSettings::OperatorDataTable`：
  - **不用** ASC 自带 `DefaultStartingData`/`DefaultStartingTable`——它在组件 `OnRegister()` 即应用（早于选角）、为 `EditDefaultsOnly` 类级配置（每角色一份会资产爆炸），且其行结构 `FAttributeMetaData` 引擎源码自注 "Still a work in progress"。

- 案 B（自定义 AttributeSet 风格组件）**未采用**——项目已在 `BattlePlayerState` 持有真 GAS `ASC`，无需自造等价物；若将来去 GAS 化再回看。
- 施工前置：`UAbilitySystemSettings` 两格在编辑器填值（`AttributeSetClass` 指 **`UOperatorBasicAttributes`**（真身，`Battle/GAS/Attributes/`，七项声明见卷 `06` §2.1）、`DamageEffectTemplate` 指伤害 GE 资产），否则 `GetDamageEffectTemplate()` 的 `check` 直接崩。

始终遵守：**属性修改只经"效果提交"入口；来源追溯（谁打的）从第一天生效**（卷 `06` §2.1/§5）。

## 2. 属性承载（卷 `06` §2.1/§6）

- `Health / MaxHealth / Shield`（`FGameplayAttributeData`）：默认满血；三者初值来自对局配置 `FOperatorCardInfo`（`Health`/`MaxHealth`/`Shield`，`Toolkits/ArkWarOperatorTypes.h`）。
- **初始化 = 选角落定后逐项 `SetNumericAttributeBase`**（§1）：落点取 `ABattlePlayerState::InitOperator`（`BattlePlayerState.cpp:118`），由业务入口 `ApplyOperatorSelection`（`:179`）在 `Comp->CheckOperatorSelection` **之后**调用；顺序 `MaxHealth → Health → Shield`。
- **入口链**（收发口归 PC 的定案见 `11` §5.2）：UI → `ABattlePlayerController::TrySelectOperator`（内转 `Server_SelectOperator`）→ `ABattlePlayerState::ApplyOperatorSelection` → `InitOperator`。
- **属性集另有四项不在 P4**：`MaxHandCardAddition` / `AttackDistance` / `DefendDistance` / `AttackReach`（`OperatorBasicAttributes.h` 已声明）——同源自干员表 `FOperatorCardInfo`，但各自的读取方（手牌配额、距离校验 `05` §4）尚未落地，**P4 不灌值、不验收**；干员表亦未列这四列（卷 `06` §2.1"列与声明两本账"）。
- 属性值复制到客户端（OnRep 供生命条/伤害数字/护盾条），**仅服务器写**。
- `Health` 与 `Shield` 各 Clamp 下限 0（落 `PreAttributeBaseChange`，§1）；**P4 不引 `MaxShield`**——盾只被伤害扣减、不被补充，无上限使用者（§6）。
- 触发**阈值钩子**：`Health 达到 0` 的瞬间广播"濒死信号"（P5 前仅 Log+占位委托，不产生行为）。

## 3. `UDamageTransaction`（基类 `04` §4.1 + 折叠 `04` §4 + 卷 `06` §3/§4）

字段关系（写死，杜绝"基类已有 `Instigator/Targets` 还要再填一套"的漂移）：
- **承受者 = 基类 `Targets` 首元素**，本族语境称 `Victim`：单目标阶段读 `Targets[0]`，**不另建字段**；P6 接多目标时按 `Targets` 全量展开（分配逐目标各算一次）。基类 `Targets` 本就是 `TArray<TWeakObjectPtr<AActor>>`（`BattleTransaction.h:55`），无需扩容。
- **`Source`（伤害归因）默认 = 基类 `Instigator`**：`Execute` 开头做**归因回退**（`Source` 无效 → `Source = Instigator`），直伤无需重复填——基类 `Start` 非虚、不写任何族字段（`04` §2，族上下文一律族自收），不落在此处；仅**转移/间接伤害**由转移路径在创建时显式填 `Source`——例：A 受杀、发动技能转移给 C，则 `Instigator` = A（交易发起方）、`Source` = 出杀者（因果归因，`06` §5 来源链末端）、`Targets[0]`(Victim) = C。裁决（击杀归属/来源死亡/来源追溯）只读 `Source`，不读 `Instigator`。

```cpp
UCLASS()
class ARKWARS_API UDamageTransaction : public UBattleTransaction
{
    GENERATED_BODY()
public:
    /* 其他成员（基类 §2 生命周期成员与 `04` §4.1 上下文/收敛形状，见 UBattleTransaction 头文件，不重复声明） */

    // ── 族语义扩展（上下文与收敛形状在基类 `04` §4.1，不重复声明）────
    TWeakObjectPtr<APlayerState> Source;            // 伤害归因来源（默认 = 基类 Instigator；转移/间接伤害时显式覆盖）
    int32 BaseAmount = 0;                           // "底"：来源侧原始值（Execute 前不变，追溯/审计用）
    FGameplayTagContainer DamageTags;               // 类型标签（卡/技能/忽略护甲/忽略护盾等；原生标签）
                                                    // 现有标签族无伤害类型命名空间，本族落地时自建
                                                    // （建议 Damage.Trait.*，实际名以落地为准；见 §3 分配步）

    // ── 结果位（本族 FoldMods() 按 `04` §4 公式折叠回填后提交）─────
    int32 Amount = 0;                               // 初始 = BaseAmount；折叠后 = 最终值（"瞬时的 current"）
    // 无 bIgnored 结果位（定稿 (a)，P3 §7 已结）："免疫/被防" = Override(0) 折零表达，
    // 由族在 Execute 开头自判 Amount <= 0 → Finish(false) 收口（移动族同款已落，2026-09-16）
    virtual void Execute() override;                // 开头调本族 FoldMods()（归并基类 ModeRequests → 本族结果位）；结尾自收尾 Finish(bool)
protected:
    virtual void FoldMods() override;               // 族实现 `04` §4 三步折叠：短路项 → (Amount+ΣAdd)×ΠMultiply → Clamp 上限；回填后清空
                                                    // 短路项 = Override 终局覆写（定稿 (a)，P3 §7 已结）；移动族同款已落 =
                                                    // Override 终局短路 → (_Count+ΣAdd)×ΠMul → Clamp(0, 封顶)，全程 float 域、末次 RoundToInt 回填
};
```

`Execute()` 服务器主流程：

```cpp
// 0. 归因回退（族自收，`04` §2：基类非虚入口不写族字段）：`Source` 无效 → `Source = Instigator`（转移/间接伤害已在创建时显式填）
// 1. 折叠收敛（`04` §4）：开头调本族 FoldMods()（覆写实现三步折叠），归并基类 ModeRequests
//    → 回填 Amount 并清空（同步无窗口 = BaseAmount）
if (Amount <= 0) { Finish(false); return; } // 被防止不落子：族 BroadcastFinish(false) 广播 Event.Notify.Damage.Prevented
//   旧稿为 bIgnored || Amount <= 0；无 bIgnored 标志位（定稿 (a)，P3 §7 已结）："免疫"以 Override(0) 折零表达
// 2. 【盾血分配】一次决策、两份落值（见下方"分配步"）：
const bool bIgnoreShield = DamageTags.HasTag(/* Damage.Trait.IgnoreShield */);
int32 ShieldPart = 0;
int32 HealthPart = Amount;
if (!bIgnoreShield)
{
    const int32 ShieldNow = /* 承受者 Shield 的 CurrentValue */;
    ShieldPart = FMath::Min(ShieldNow, Amount);   // 盾不足则吃完为止，余量归血
    HealthPart = Amount - ShieldPart;
}
// 3. 构造"修改声明"（案 A：动态 GE + SetByCaller）：
//    Shield -= ShieldPart；Health -= HealthPart（分量为 0 的那笔不构造 Modifier）
//    标签带 DamageTags + Instigator=Source（因果来源 = 本族 Source，`06` §5）
// 4. 应用 → 属性落值（含 Clamp）
Finish(true);   // 唯一收尾；族 BroadcastFinish(true) 广播 Event.Notify.Damage.Applied（Amount 修正后值、来源、承受者、类型）
```

- `Finish(false)` 在此的语义 = "被防止、未造成任何修改"，符合卷 `04` §2（不 Execute 的终局，**无 `Cancel` 第二入口**）；**防止≠空转**——族 `BroadcastFinish(false)` 已广播 `Prevented`，UI/语音有据可查。
- 目标侧"死亡/离场"未发生时正常应用；若窗口期目标死亡（跨窗竞态）→ 目标失效规则（卷 `05` §2）终止本次结算，走 `Finish(false)`。

### 3.1 分配步：先破盾后掉血为何在交易层

**先破盾后掉血不是减伤，是分配**——两者正交，各归各家：

| | 干什么 | 归谁 |
|---|---|---|
| 减伤 | 把 `Amount` 从 100 压到 60 | `FoldMods()`（交易层已有） |
| **分配** | 60 点里盾出 20、血出 40 | **本步（交易层新增）** |

**不落 `PreAttributeChange` / `PreAttributeBaseChange`**：
- 钩子**按属性逐个触发**，看不到另一属性——伤害到 `Health` 的钩子时，这笔修改**已被拆开**，而分配本该在拆之前决定。
- 若在 `Health` 钩子里反手扣 `Shield`，会引发**嵌套修改**（改 Shield 触发 Shield 的钩子，而 Health 尚未收尾）。引擎源码明示（`AttributeSet.h`）：Pre 钩子 *"is meant to enforce things like `Health = Clamp(Health, 0, MaxHealth)` and **NOT** things like 'trigger this extra thing if damage is applied'"*——**只做钳制，不做业务逻辑**。破盾是业务逻辑。
- 分配若在此，技能在窗口期想说"本次无视护盾"就没有落脚点——窗口开在属性修改**之前**，那会儿分配还没发生。

**不落 `UGameplayEffectExecutionCalculation`**：
- Execution 在 `ApplyGameplayEffectSpec` **内部**跑，而项目的窗口开在应用**之前**（§4）——技能追加的修改早已折进 `Amount`，Execution 再算一遍分配即等于在时机总线之外另开决策点，违卷 `06` §6"**GAS 不裁决时序**"。
- 它改两属性会触发两个 `PostGameplayEffectExecute`，**先后无序**，给不出"盾破了"这样的**整体语义**。
- 绕远：`Amount` 已是交易层的收敛结果，塞进 `SetByCaller` 传给 GE 再让 Execution 拆一遍，等于把逻辑从 `.cpp` 搬进 GE 资产——调试要先找资产再找 Execution 类。

**落本处（`Execute` 第 2 步）**：
- `DamageTags` 本就在交易上（"忽略护甲"已是同族先例，无视护盾不过多一枚标签，§3 字段）。
- **前后各归其位**：窗口期在 `FoldMods` 之前（技能干预的是**总量**），分配在 `FoldMods` **之后**（用的是**收敛后的值**）。谁也没越界。
- 分配是**一次决策、两份落值**——收尾 `Finish(true)` 时能一并广播"盾挡了多少 / 血掉了多少 / 盾是否破"，AttributeSet 的逐属性钩子给不了这个整体语义。
- 分量为 0 的那笔**不构造 Modifier**（只掉血或只破盾时是单笔修改，不是带 0 的两笔）。

**扩展位（P4 不落，仅记形状）**：将来"盾受到的伤害减半"一类技能改的是**分配规则**而非 `Amount`，应走与基类 `ModeRequests` 同族的**"分配规则请求"**通道（在分配步归并），**不**混进 `Damage.PreHurt` 的数值修改请求——否则语义就歪成"改了总量"。P4 不落该通道，等首个真实技能（P6/P7）再开。

## 4. 伤害时机族接线（登记卷 `03` §6）

| 时机/事件 | 通道 | 谁开 | 用途 |
|---|---|---|---|
| `Event.Timing.Damage.PreHurt` | 查询窗口 | `QueryTimings()`（P4 实现） | 承受者侧减免/防止/转移 |
| `Event.Timing.Damage.Dealt` | 查询窗口 | 同上 | 来源侧加成/锁定（P6 批量） |
| `Event.Notify.Damage.Applied / Prevented` | 事实通知 | `Execute` 内广播 | UI 伤害数字、技能订阅（如"受伤后回状态"） |

> **命名以代码为准**：本族查询时机在 `EventTags.cpp:67-68` 定义为 `PreHurt` / `Dealt`（`EventTags.h:40-45` 的 `Timing::Damage` 命名空间）。本指南旧稿及各卷正文中的 `Damage.Incoming` 是其**同义旧称**，卷 `03` §3.1 已声明"代码命名与本卷差异以代码为准"（对照见 `12` 附录 B/C）。施工一律用 `PreHurt`。

伤害链与"减伤技"的关系 = 技能体挂 `Damage.PreHurt` 窗口**追加修改请求**（`Override(0)` 折零短路（原 `Ignore`，定稿 (a)）/ `Clamp` 封顶 / `Add` 加（负值 = 减）/`Multiply` 倍率——**无独立 Sub/Div Op**，减 = `Add` 负值、除 = `Multiply` 倒数；多修改收敛定序见 `04` §4）；**全引擎无伤害特判**（案例模板在卷 `06` §10、样板在 `09` §11）。

**窗口改的是 `Amount`，不是分配**：技能在 `PreHurt` 里追加的是**总量**修改（减伤/防止/转移），收敛后才是 `Amount`；盾血分配发生在收敛**之后**（§3.1），技能不能直接改"盾承担多少"——要改那是"分配规则"的活，走独立通道（§3.1 扩展位），P4 不落。

## 5. 验收

1. 初始化：选角落定后 ASC 三属性 = `FOperatorCardInfo` 初值；`MaxHealth` 先于 `Health` 落（反序则 `Health` 被钳 0，见 §1）。
2. 测试技/调试入口：对一目标结算 `UDamageTransaction(Base=1)` → 目标 `Health -1`、通知 `Applied`、客户端生命条变化。
3. **分配三分支**（§3.1）：
   - 盾足（`Shield ≥ Amount`）：`Shield -Amount`、`Health` 不变、盾条变化；
   - 盾不足（`0 < Shield < Amount`）：盾归 0、`Health -= (Amount - Shield)`（**两笔落值**）；
   - 盾空（`Shield == 0`）：全归 `Health`（单笔）。
4. 减免：另一测试技挂 `Damage.PreHurt` 追加修改请求（`Add(-1)`（减 1）或 `Clamp`（上限 1））→ 折叠后结算正确；`Override(0)` 折零走防止路径（`Finish(false)`/`Prevented` 日志与通知）——**注意折零在分配之前**，被防止时不产生任何落值。
5. 来源追溯：`Applied` 通知携带 Source；从通知可回溯到发起者。
6. 阈值占位：`Health` 归 0 触发占位钩子（Log），不崩溃、不产生行为。
7. 复制：服务器数值与客户端 OnRep 一致；客户端无写入路径。
8. 回归：P2/P3 全绿（移动、窗口、忙锁不破）。

## 6. 边界（不碰）

- ❌ 濒死求回应/死亡淘汰/伤害后处理链——P5（阈值钩子占位）。
- ❌ 持续状态/GE 到期/层数——P7（P4 只应用"一次性即时修改"）。
- ❌ 复杂目标（多目标/目标规则）——P6。
- ❌ 治疗/流失等非伤害修改——P6/P7（本阶段先只通伤害一例，形状复用）。
- ❌ **护盾的补充/重置/上限**——P4 的盾只有"选角初值 + 被伤害扣减"两条路径，无 `MaxShield`、无给予手段（§2）。
- ❌ **分配规则的可干预通道**——P4 分配写死"盾优先吃满、余量归血"；"盾伤减半"一类改规则的技能走独立通道（§3.1 扩展位），P6/P7 再开。
- ❌ **`MaxHandCardAddition` / `AttackDistance` / `DefendDistance` / `AttackReach` 的灌值与读取**——属性集已声明、干员表将给值，读取方随各自归属卷落地（§2）。
