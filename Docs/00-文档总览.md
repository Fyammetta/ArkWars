## 3. 编号与命名约定

- 卷文件固定前缀 `NN-`；阶段文件 `P{阶段}-`。
- 每卷自带：**职责边界 → 与邻卷依赖契约 → 抽象 → 流程 → 扩展点 → 案例（非框架）**。
- 阶段文件统一：**目标 / 输入(依赖已完成的零件) / 施工内容(引用卷中章节) / 验收 / 边界(本阶段不碰)**。
- 时机/事实标签、区域标签等命名规范见 `03-时机与事件模型` §3 与 `08-卡牌与容器模型` §2，跨卷复用。

## 4. 三句话总纲（整套文档的设计契约）

1. **低耦合**：任何一卷只通过**接口与标签**与外界对话，不反向依赖实现；流程引擎不认具体卡牌，结算引擎不认具体技能。
2. **高扩展**：新增"机制" = **数据组合 + 接口实现**（时机标签 × 交易类型 × 目标规则 × 频率限制 × 响应链 × 效果），不新增引擎分支。
3. **不针对机制**：具体牌/技（杀、闪、无懈、濒死求桃、判定改判……）一律只出现在各卷「案例」小节，作为**验证与数据样本**，不进架构结构；引擎只提供它们共用的抽象形状。

## 5. 术语速查

| 术语 | 含义 | 出处 |
|---|---|---|
| 事实通知 / 查询时机 | 已发生（不可否决）同步多播 / 将发生（可干预）异步窗口 | 卷 03 |
| 交易（Transaction） | 有生命周期的结算对象，是"悬置"的停泊点 | 卷 04 |
| 响应窗口 / 响应链 | 时机开放给合法响应者的询问窗口；链 = 可嵌套的抵消/回应序列 | 卷 03、10 |
| 事件与委托登记册 | 跨卷集中登记：事件名 / 广播者 / 广播时机 / 订阅者 / 登记方式；新增事件须回填 | 卷 12 |
| 通知链路 | 开窗 → 通知（`FWindowOpened` + 逐个询问）→ 响应者主动 `AppendModification` → 关窗；ModRequest 非推送 | 卷 12 §4、04 §4.1 |
| 交易嵌套 / 排队 | 插入交易两条路：排队（`EnqueueTransaction`，不打断）vs 嵌套插队（`PushNestedTransaction`，挂起当前先结算子交易）；只能在交易边界发起 | 卷 04 §3.2、12 §6 |
| 频率账本 | 每回合/每轮/整局 N 次的通用计数与上限裁决 | 卷 07 |
| 使用门槛 | 目标描述解空 ⇒ 无"使用"入口；裁决只读、无原因分类、服务器复判 | 卷 05 §3.2 |
| 转化 / 视为 | 出牌素材：转化 = 消耗一张实体牌、以其花色点数当作指定特定牌打出；视为 = 不消耗实体，直接使用/打出一张无花色点数的虚拟选定牌 | 卷 08 §7.2 |
| 卡牌标记 | 挂在牌实例上的效果来源（干员技能授予等）；典型用法是授权该牌"当作某特定牌使用/打出" | 卷 08 §7.3 |
| Tag 生命周期 | 牌上衍生标签何时终结的统一模型：终结原因收口为三类（主动移除 / 离开附加者(任意区域) / 进入弃牌堆），类别由数据声明，执行位在两跳之间 | 卷 08 §7.6 |
| 判定区收单/结算 | 同种唯一收单 + 判定阶段 LIFO 结算 + 转移顺延 | 卷 08 §8 |
| 效果描述符 | 交易/技能产出效果的数据化形态（对状态/数值的修改声明） | 卷 06、08 |
| 技能演化 | 觉醒/修改技的通用处理：修改即建立独立演化副本 | 卷 09 |
| 卡牌值类型 | 存放/移动层统一载体 `FArkCard{ Id, Tags }`：`Id` = 服务器分配实例身份（整局唯一），`Tags` = 语义标签（谓词/条件只读它） | 卷 08 §7.1 |
| 出牌素材 | 使用/打出入口拿到的"这一张"：`FCardMaterial{ Kind(实体/转化/视为), Presented }`；`Presented.Id` 指向被消耗实体（视为 = 0） | 卷 08 §7.2 |
